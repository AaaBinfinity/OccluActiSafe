# N02 数据契约字典

本字典保留 N02 的待实施接口设计，拟用 schema 版本 `1.0`。2026年10月29日按用户确认恢复编码前状态，相关实现与测试已移除，N02 未开始、未测试、未验收，须在 N01 重新验收并单独授权后实施。下文所有模块、函数、配置和测试路径均为拟建，行为与断言是设计要求，不表示已有可调用接口。历史实测由 Git 追溯。

## 公共单位与时间

- 平面为右手系，位置和尺寸为 m，速度为 m/s，时间为 s，航向为 rad；`coordinate_frame_id` 指定坐标系，`frame_id` 是非负采集/仿真帧号，二者不能互换。`reference_point` 只接受 `geometric_center` 或 `rear_axle`；统一变换拟位于 `common/coordinates.py`。
- 每个对象的 `clock_domain` 必须明确；组合对象及接收记录要求域一致。消息保留采集、最后真实观测、源处理完成、外推状态、锚点/截止、计算完成、生成、发送等独立时刻；接收时间只能在接收侧 `ReceivedMessage` 中提供。
- `valid_until` 是最后可采用时刻，`future_end` 是预测覆盖终点；二者不强加先后关系。发送时不得已过期，接收后过期仍可记录，但不能消费。计划 `deadline` 是任务截止，允许早于 `plan_start_time`。消费方需调用 `ReceivedMessage.require_available(Timestamp(...))`；对象构造或到达不等于能消费。

## 对象与字段

| 对象 | 主要字段和含义 | 核心校验与边界 |
| --- | --- | --- |
| `EgoState` | `ego_id`、时钟与坐标系、参考点、`observation_time/source_available_time/state_time`、`x/y/vx/vy/yaw/length/width`、速度与航向有效掩码 | 本车位置和尺寸必填；未知速度与航向为 null 并设置掩码，不能与零混同 |
| `SourceTrack` | 来源/会话/传感器/局部 track 标识、类别与 `ego/target` 角色、坐标和参考点、`observation_time/last_seen_time/source_available_time/state_time`、位置/速度/航向、尺寸来源、可空尺寸不确定度、可空二维位置协方差、质量与有效掩码 | 类别为 vehicle/pedestrian/cyclist/unknown；缺位置、速度、航向或尺寸分别使用 null 与对应掩码；协方差需有限、对称且半正定；未知不确定度为 null |
| `ObservationPacket` | 地图及版本、坐标、帧号、时钟域、采集/可用时刻和 `tracks` | 目标域/坐标必须一致；目标采集、源可用及状态时刻不能晚于包的相关时间 |
| `PredictionBundle` | 内部 NumPy `trajectories[B,N,K,T,2]`、`weights[B,N,K]`、`valid_mask[B,N,K,T]`、`future_times[T]`、锚点/输入截止、模型/坐标/时钟标识 | 形状一致、数值有限、掩码为 bool；有效目标各模式权重非负且和为1，无效模式权重为0；数组拷贝且只读；不提供 JSON 序列化 |
| `PredictionTarget` | `track`、二维轨迹 `[K,T,2]`、权重 `[K]`、各模式时间有效掩码 `[K,T]` | 目标状态、类别、来源与质量随预测保留；有效掩码可表示终点提前；目标的 K/T 不跨消息默认假设 |
| `ObservationMessage` / `PredictionMessage` | `schema_version/message_type/source_id/session_id/sequence/recipient_id/map_id/map_version/coordinate_frame_id/frame_id/clock_domain`，生成/发送/有效期及各自观测或预测字段 | 发送侧白名单；预测另带 `model_hash/anchor_time/input_cutoff/completed_time/future_times/future_end/targets`；不得包含 `arrival_time/usable_time` |
| `ReceivedMessage` | 原始 `payload`、接收侧 `arrival_time/usable_time/clock_domain` | 发送≤到达≤可用，接收域与发送域一致；调用 `require_available` 再检查决策时采集、处理、状态、接收和有效期 |
| `DecisionBundle` | 决策模式、原因、请求 ID、参考轨迹、计划起点/截止/有效期、风险口径及数值、风险时域/参考策略、约束上下文 | 未校准评分、校准事件概率和未知区域约束分开；概率在 [0,1]，未知区域约束不伪造风险数值 |
| `ControlResult` | 请求/计划 ID、求解状态、安全复核、计划起点/有效期、归一化油门/制动/转向、回退原因 | 成功必须经安全复核；非成功必须有原因；油门与制动互斥；控制范围检查不表示实车控制已验证 |
| `TickEvent` / `AdvanceRequest` | run、episode、generation、帧号、仿真时间与合法观测；或目标帧、请求时间、有效期及控制 | 严格字段白名单排除真值；事件内观测已采集且源处理完成；请求和控制时钟域一致，请求期限不超过控制期限，控制（含回退）必须复核；目标帧是否处于执行有效时段由后续桥接调度核验，不把请求时间当执行时间；只定义契约 |
| `NoResult` | 任务 ID、时钟域、时间和失败/无结果原因 | 明确无结果不表示目标消失 |

拟在 `src/occluactisafe/common/schemas.py` 定义数据类，字段白名单应拒绝缺字段、未知字段、重复 JSON 键、类型错误、NaN/Infinity 和不支持的版本；输入输出不承载仿真真值与未来标签。拟在 `core/interfaces.py` 仅声明路侧、车端决策与执行器的 `Protocol`，不实现感知、预测或控制。JSON 类型拟提供 `to_json()/from_json()` 与 `to_dict()/from_dict()`；`ReceivedMessage` 仅作接收侧封装。拟建黄金消息 `tests/fixtures/n02/` 与 `tests/unit/test_schemas.py`，验证合法往返、无效数据、接收时序、目标掩码、数组及桥接消息；这些夹具不是真实数据或实验结论。

**与车路主方案的对应：** I端拟将状态和预测一起提供给V端；拟定`PredictionMessage.targets`中每个`PredictionTarget`含`track`（`SourceTrack`目标状态）与`trajectories/weights/valid_mask`。`track`保存来源、原始观测/状态时刻及有效掩码，预测对象保存预测锚点和未来时域；两者不能因打包而假设时间相同。仅状态可用时，可用拟定`ObservationMessage.tracks`表达可用目标状态，两类消息各自具有自己的发送/接收时序，不能假设一定配对或同时到达。I2V发送调度、缺失/覆盖处理及车端本地预测回退是后续拟实施行为，此处只解释拟定字段，不新增schema字段或声称链路已实现；V端最终风险和动作由后续决策模块完成。

## 配置、时空与运行清单

- `common.config.load_config()` 输入所选 YAML、脚本 `overrides` 与显式 `cli_overrides`，按包默认→`configs/base.yaml`→所选任务→脚本覆盖→CLI 合并；`config_file` 替代默认任务文件，未提供的 CLI 值不覆盖配置。未知字段、重复 YAML 键、非法数值和不满足周期整数倍的配置被拒绝；相对路径按项目根解析。`parse_config_cli(argv)` 仅解析当前公共选项并拒绝未知参数。
- `common.coordinates` 使用米和逆时针弧度，世界/局部变换及参考点偏移共享一套函数；CARLA 平面位置、速度和朝向转成右手系。`common.clock` 用 `Timestamp(seconds, clock_domain)` 校验同域、各字段因果关系及决策时可用性。可用性检查须由调用方提供该对象适用的全部时间字段，不自动代替后续通信模块的调度。
- `common.run_manifest.create_run_manifest()` 输入完整解析配置、输入模式、公开数据标识及其 SHA-256（或 `None`）、输出根，生成唯一 run ID、`manifest.json` 与 `resolved_config.yaml`，记录 Git 提交、工作区是否有改动、源码范围哈希、配置哈希和环境。相对输出路径基于项目根；后续拟使用 uv 可编辑安装，其他安装方式须显式指定 `project_root`。函数拒绝未知配置字段、常见敏感键/值及 URL，但无法识别所有可能的秘密；调用方必须只传公开的配置、路径和数据标识，不传凭据。
- 配置优先级、非法值、跨目录与清单测试拟建于 `tests/unit/test_config_manifest.py`；坐标手算/往返及时钟负例拟建于 `tests/unit/test_coordinates_clock.py`；消息、桥接与黄金样本拟建于 `tests/unit/test_schemas.py` 和 `tests/fixtures/n02/`。测试输入应使用构造夹具；未来实际运行清单与测试证据须回填节点计划，当前没有可用于验收的本节点测试结果。
