# N14 固定盲区路口与配对 AEB

本节点是 `trajectory_input`：CARLA 当前可见目标的标注状态经适配层和通信时序过滤后供 CV-AEB 使用。RGB 是真实仿真画面及可见性核验证据；没有运行检测器、跟踪器、学习预测或 MPC。当前实测、代码提交和验收状态以[节点计划 N14](项目节点实施与验收计划.md#n14-固定盲区路口与受限轨迹配对aeb)为准。

## 场景、输入与适用范围

`configs/scenarios/occluded_junction.yaml` 保存实际地图发现得到的 Town10HD_Opt、junction 189、交叉路线采样点及 OpenDRIVE 哈希，车辆使用 N13 已测 Audi A2。发现入口通过官方 `GlobalRoutePlanner` 检查上下游至少70/30 m、近直线且夹角60°～120°的路线对；实际找到4组，本次按用户要求增强遮挡，选择原候选第2组并冻结为 `town10-j189-moving-firetruck-v2`，正式运行时不再选择。初始点位于冲突点前约50 m；名义目标速度8 m/s，公共运动前缀3 s。这是选取的开发演示案例，不是冻结测试集或交通法规测试。

遮挡物改为实际蓝图 `vehicle.carlamotors.firetruck`，实测包围盒长8.468 m、宽2.891 m、高3.827 m，质量10000 kg。主车在 road20/lane5、大车在邻接 lane4，均为 Driving 车道且同向，中心横向相距3.5 m，大车参考点初始领先4 m；保存实际车道类型、车道航向和车体姿态核验，避免旧场景大车与所在车道反向的问题。大车以自身状态跟随8 m/s参考速度，车头距冲突线≤7 m后锁存全制动让行；本轮实际最小车头余量2.316 m，验收下限1.5 m。大车车体不越出3.5 m车道，无主车/目标车接触，不能借大车撞停目标获得“避撞”。

静态对照另起世界，在协同触发时刻3.05 s的三车平面位姿落地后冻结；仅把大车移开1000 m，分别保存真实图像和目标像素。该离线可见性核验允许使用评测位姿，不把隐藏状态送入在线策略，也不是避撞反事实。主实验大车保持真实物理运动。

车端相机1280×720、水平FOV90°，相对自车 `(1.5,0,1.6)m`、向来车侧偏转−12°；路侧相机高7 m，实际位置、朝向和俯仰见冻结配置。按FOV计算的名义针孔内参为 `fx=fy=640, cx=640, cy=360`（不表示N18投影误差已验收），各运行另存实际外参矩阵。车端与路侧 RGB 各有同位姿的实例相机作为仿真标注可见性核验；依照 CARLA 官方示例 `bounding_boxes.py` 和[实例相机说明](https://carla.readthedocs.io/en/0.9.16/ref_sensors/#instance-segmentation-camera)解码 `actor_id=G+(B<<8)`，只接受同帧且至少1个目标可见像素。两端有效范围均100 m，取消旧28 m车端范围差异。新增相对主车 `(-7,0,3.5)m`、俯角−14°的跟车 RGB，仅用于展示，不参与可见性或决策。

实例相机ID、完整世界状态、实际未来和碰撞事件只留在桥接评测侧。当前标注位置/速度仅在目标确实可见且在有效范围内时转成 `ObservationPacket` 或 `PredictionMessage`；完全隐藏时不传坐标。该轨迹输入不含图像检测误差，不表示视频感知能力。

## 2026-11-01已授权的触发规则修订（正在复测）

用户明确要求“提前发现风险时先预警，根据当前速度、执行延迟、实测制动能力和安全余量判断何时紧急制动；重跑并增加俯瞰实景/实时俯瞰示意图”。本次仅修订N14；下文早期立即全刹及旧结果属于旧被测版本，待本轮真实复测后统一更新当前结果，不改写硬盘旧证据。

冻结规则：两种AEB共享未来3秒CV圆包络风险检查。先求合法当前轨迹外推后的圆包络首次接触时间t_entry；剩余可行驶距离D=v×t_entry。预算B=v×(N13响应延迟0.15秒+控制周期0.05秒)+v²/(2×N13实测减速度7.378285614969219m/s²)+5米安全余量。风险存在且D>B仅预警，D≤B且公共3秒前缀已结束才锁存全刹；参考分支始终不干预。预警阶段保持既有定速控制，无人为固定延迟，无读取隐藏目标/实际未来。路侧目标只缓存已经usable的消息，限于消息valid_until及state_time后0.5秒，按当前时刻CV补偿；本地仍只消费当前合法可见轨迹。输出模式、首次预警/制动时刻、包络接触时间、D/B/余量、来源/年龄和当前CV预测点供在线俯瞰展示；目标未知时不绘制目标真值或预测。

新增测试输入为距离24米的交叉来车（预警、不制动）、距离12米（预算不足、制动），以及8/4m/s速度、0.15秒延迟、0.05秒周期、8m/s²减速度、5米余量（预算分别10.6/6.8米），验证跨消息间隔缓存及过期、仅车端不使用路侧、前缀与锁存、未来/真值字段拒绝。尚未将机制通过记作真实复测通过；本轮场景、视频和可视化验收仍须完成。

| `scripts/run_occluded_junction.py` | 默认YAML或可选CLI → 三分支子进程和完整记录 | CARLA仅由独立桥接Python导入；核心通过逐行JSON读合法观测并返回互斥、有限的控制；原始数据不经核心读回 |
| `evaluation/episode_metrics.py` | 当前评测状态 → OBB重叠和规范JSON哈希 | 只做旁路，不把几何重叠混为传感器实际碰撞，不把隐藏状态返回策略 |
| `scripts/analyze_occluded_junction.py` | 三分支原始记录 → 逐项断言、差异CSV、图表和MP4 | 验冻结身份、初态、运动前缀容差、消息时刻、停车空间、道路走廊和实际事件；任何失败非零退出 |

| `scripts/verify_n14_occlusion.py` | 两次同位姿静态渲染 → 遮挡对照与来源哈希 | 车辆位置/航向一致；大车存在时车端像素0，移开后>0，路侧两次>0；不改变主实验未来 |

大车机制夹具见 `tests/unit/test_n14_occluder.py`：冻结停车线x=0、车长8.5 m、目标速度8 m/s；自身x=−30 m且沿车道8 m/s时断言正油门、零制动/转向；x=−10 m时车头余量5.75 m，断言全制动并在回到x=−20 m后仍锁存；同一x=−10 m但处于初始化时断言不误触发。机制日志保存为本轮证据目录的 `N14新版机制测试.log`，真实大车状态/控制及两类接触事件另存主运行各分支JSONL/JSON，机制夹具不替代真实三分支验收。

坐标统一为项目右手系 `X=CARLA.x, Y=-CARLA.y, yaw=-yaw_CARLA`，状态参考点是车辆几何中心。三分支分别为参考行驶、仅车端AEB和协同AEB。路侧每0.1 s用当前合法轨迹生成4 s CV预测，复用 N08 `SimChannel`：传播0.20 s、接收处理0.05 s、无丢包/抖动，seed 20261031。该信道是因果软件模型，没有无线硬件性能结论。

在线 AEB 只从合法当前状态做 CV 相对运动外推，在未来3 s内计算最近接近；以两车外接圆半径之和作为保守触发包络。它不是已校准的碰撞概率。公共前缀内三分支执行相同参考控制；之后参考分支不干预，仅车端忽略路侧包，协同分支须等 `arrival_time` 和 `usable_time` 后才消费，风险触发后锁存全制动。

参考行驶及横向车使用 N13 的速度分档前馈和 PI（`kp=.05, ki=.02`）、转角映射及归一化转向变化率限制。初始化先落地及实际油门预热，再在正式时钟启动前一次恢复已落地位姿和初速，避免旧版恢复z=0.5造成初始下落。三车姿态、速度初始化及每帧控制均通过 `apply_batch_sync(...,False)` 同步下发，只有既有runner推进一次；正式运行中不再设置位置/速度。制动阶段仍使用 N13 已测全刹车及停车保持，低于映射最低速度时不外推 PI 表。Audi物理参数与 N13 上下文逐项核验；大车为外生场景脚本，不声称其已获N13标定。未改AEB算法、标定或舒适性标准。

## 配对、测试和留证

用户于2026-10-31批准了运动前缀容差：位置差≤0.10 m、速度向量差≤0.15 m/s、航向差≤0.001 rad、归一化控制差≤0.01。场景/扰动身份及初态哈希必须一致；原始前缀哈希各自保留，记录两对分支逐帧差异，消息序号、到达/可用时刻和队列数量必须相同。任一超限判配对失败，不能把不同物理前缀写为逐位一致。

按 C07/F01 检查：参考分支的声明冲突必须由真实碰撞传感器及几何事件分别留证；协同分支有足够经实测标定的制动空间、停车、无碰撞、无道路走廊越界；触发时实际车端目标像素必须为0而路侧>0；消息可用前不得影响控制。原标准允许仅车端同样成功；用户本次明确要求找一个仅车端碰撞的示例，当前冻结配置追加 `require_local_collision: true`，必须真实传感器碰撞及OBB事件，不修改策略制造结果。另查起始至协同触发持续完全遮挡、三车公共前缀差异、同向合法车道、大车无接触及停车线余量、实际连续制动且无位置跳变。本轮场景断言36项，机制测试10项（新增大车驾驶3项）；只代表本开发案例。

任一分支在碰撞后结束，未碰撞分支至10 s；不补齐或回放另一分支的未来。保存原始合法观测、决策、实际轨迹、碰撞传感器JSON、消息事件、每分支清理报告、源码和配置哈希；大车和目标的碰撞旁路分别记录。相机每0.05 s留三视角原始1280×720 PNG，另存碰撞触发帧；三份双视角视频与一份仅车端/协同跟车同步对照均为2560×720、原始20 fps，不插帧。跟车视频叠加实际速度、实际制动量和纵向加速度；左侧碰撞后末帧停留明确标注，速度标为碰撞前末次采样，不杜撰碰撞后的运动。输出逐帧制动响应CSV与PNG/SVG，原值不平滑。图片、视频和原始记录放 H 盘原运行目录，中文命名并使用归档脚本复核；Git只保存代码、配置、Markdown和位置/哈希清单。

IDE日常入口是 `scripts/run_occluded_junction.py`，默认无需CLI；先人工启动本机匹配版本的CARLA服务。首次桥接依赖单独按 `configs/runtime/n14_bridge_requirements.txt` 准备，视频组为 `uv sync --group simulation-video`，不会由日常入口自动安装。分析可使用 `--run-dir` 明确指向本次目录；默认选择最近完整三分支运行。所有脚本从文件位置解析仓库根，不依赖启动目录。

用户于2026-11-01要求每种AEB、每个已采集角度各存独立视频。IDE直接运行 `scripts/export_n14_camera_videos.py`，默认只读取最终运行 `n14_110af5fc4b354cf7b149030bf4c15921`，可选 `--run-dir` 指定其他实际运行；无需CARLA服务。输出原运行目录下 `独立视角视频/<导出ID>/`，中文命名且拒绝覆盖，原视频/清单不改写。仅车端AEB及车路协同AEB各导出车内前向（原车端相机，无仪表台内饰）、路侧、跟车3个角度。使用现有Pillow与imageio-ffmpeg，以CPU/libx264、CRF18、yuv420p编码；MP4为有损编码，原始PNG继续保留。保存972条输入帧来源/哈希和6份逐帧解码结果，实际仅车端每角度124帧/6.2秒、协同每角度200帧/10秒；两者最后原始采样时刻分别6.15秒/9.95秒，编码时长按帧数/20计算。独立视频不叠加文字，遥测仍看既有跟车同步对照及原始CSV。此为同次实际仿真的补充导出，不增加场景或改变碰撞结论。
