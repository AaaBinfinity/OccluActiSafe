# N14 固定盲区路口与配对 AEB

本节点是 `trajectory_input`：CARLA 当前可见目标的标注状态经适配层和通信时序过滤后供 CV-AEB 使用。RGB 是真实仿真画面及可见性核验证据；没有运行检测器、跟踪器、学习预测或 MPC。当前实测、代码提交和验收状态以[节点计划 N14](项目节点实施与验收计划.md#n14-固定盲区路口与受限轨迹配对aeb)为准。

## 场景、输入与适用范围

`configs/scenarios/occluded_junction.yaml` 保存实际地图发现得到的 Town10HD_Opt、junction 189、交叉路线采样点及 OpenDRIVE 哈希，车辆使用 N13 已测 Audi A2。发现入口通过官方 `GlobalRoutePlanner` 检查上下游至少70/30 m、近直线且夹角60°～120°的路线对；实际找到4组，冻结第0组，不在正式运行时重新选择。初始点位于冲突点前约50 m；名义目标速度8 m/s，公共运动前缀3 s。测试区域无新增背景交通，车辆遵循冻结路线，不是交通法规或真实道路驾驶测试。

物理遮挡物为实际蓝图 `vehicle.carlamotors.carlacola`，静置于测试通道外。生成后检查其 OBB 不与主车及横向车的路线走廊相交；不会关闭其视觉遮挡来完成主实验。静态对照是另起世界、固定两车位姿、仅移开大车，分别保存真实图像和目标像素数，用于确认遮挡的物理来源，不把它当作避撞反事实结果。

车端相机1280×720、水平FOV90°，相对自车 `(1.5,0,1.6)m`、向来车侧偏转−12°；路侧相机高7 m，实际位置、朝向和俯仰见冻结配置。按FOV计算的名义针孔内参为 `fx=fy=640, cx=640, cy=360`（不表示N18投影误差已验收），各运行另存实际外参矩阵。每个 RGB 相机均有同位姿的实例相机作为仿真标注可见性核验；依照 CARLA 官方示例 `bounding_boxes.py` 和[实例相机说明](https://carla.readthedocs.io/en/0.9.16/ref_sensors/#instance-segmentation-camera)解码 `actor_id=G+(B<<8)`，只接受同帧且至少1个目标可见像素。车端有效范围28 m，路侧100 m；可用性差异同时受视角、物理遮挡和范围影响，不能全部归因于大车。

实例相机ID、完整世界状态、实际未来和碰撞事件只留在桥接评测侧。当前标注位置/速度仅在目标确实可见且在有效范围内时转成 `ObservationPacket` 或 `PredictionMessage`；完全隐藏时不传坐标。该轨迹输入不含图像检测误差，不表示视频感知能力。

## 实现和因果边界

| 入口／函数 | 输入与输出 | 实现与必需断言 |
| --- | --- | --- |
| `scripts/discover_occluded_junction.py` | 本机CARLA地图 → 硬盘候选JSON | 只读拓扑、固定排序、实际路线及地图哈希；不存在合格路线明确失败 |
| `simulation/scenarios.py::run_episode` | 冻结配置 → 白名单观测、真实控制执行及评测旁路 | 只由既有 `SynchronousRunner` 推进世界；每分支重载前固定同步0.05 s和子步；目标车按固定参考路线独立驾驶 |
| `simulation/trajectory_input.py::TrajectoryAEB.step` | 当前自车、合法本地包和已可用消息 → AEB锁存及来源审计 | 不接收 World、评测真值或实例标注；未知字段、非有限值、错误时钟/坐标/来源和未可用包拒绝 |
| `scripts/run_occluded_junction.py` | 默认YAML或可选CLI → 三分支子进程和完整记录 | CARLA仅由独立桥接Python导入；核心通过逐行JSON读合法观测并返回互斥、有限的控制；原始数据不经核心读回 |
| `evaluation/episode_metrics.py` | 当前评测状态 → OBB重叠和规范JSON哈希 | 只做旁路，不把几何重叠混为传感器实际碰撞，不把隐藏状态返回策略 |
| `scripts/analyze_occluded_junction.py` | 三分支原始记录 → 逐项断言、差异CSV、图表和MP4 | 验冻结身份、初态、运动前缀容差、消息时刻、停车空间、道路走廊和实际事件；任何失败非零退出 |
| `scripts/verify_n14_occlusion.py` | 两次同位姿静态渲染 → 遮挡对照与来源哈希 | 车辆位置/航向一致；大车存在时车端像素0，移开后>0，路侧两次>0；不改变主实验未来 |

坐标统一为项目右手系 `X=CARLA.x, Y=-CARLA.y, yaw=-yaw_CARLA`，状态参考点是车辆几何中心。三分支分别为参考行驶、仅车端AEB和协同AEB。路侧每0.1 s用当前合法轨迹生成4 s CV预测，复用 N08 `SimChannel`：传播0.20 s、接收处理0.05 s、无丢包/抖动，seed 20261031。该信道是因果软件模型，没有无线硬件性能结论。

在线 AEB 只从合法当前状态做 CV 相对运动外推，在未来3 s内计算最近接近；以两车外接圆半径之和作为保守触发包络。它不是已校准的碰撞概率。公共前缀内三分支执行相同参考控制；之后参考分支不干预，仅车端忽略路侧包，协同分支须等 `arrival_time` 和 `usable_time` 后才消费，风险触发后锁存全制动。

参考行驶及横向车使用 N13 的速度分档前馈和 PI（`kp=.05, ki=.02`）、转角映射及归一化转向变化率限制。初始化先实际油门预热，再在正式时钟启动前一次恢复冻结位姿和初速；正式运行中不再设置位置/速度。制动阶段使用 N13 已测全刹车及停车保持，低于映射最低速度时不外推 PI 表。所有物理参数与 N13 上下文逐项核验；未知附着与其他车辆不在范围内。

## 配对、测试和留证

用户于2026-10-31批准了运动前缀容差：位置差≤0.10 m、速度向量差≤0.15 m/s、航向差≤0.001 rad、归一化控制差≤0.01。场景/扰动身份及初态哈希必须一致；原始前缀哈希各自保留，记录两对分支逐帧差异，消息序号、到达/可用时刻和队列数量必须相同。任一超限判配对失败，不能把不同物理前缀写为逐位一致。

按 C07/F01 检查：参考分支的声明冲突必须由真实碰撞传感器及几何事件分别留证；协同分支有足够经实测标定的制动空间、停车、无碰撞、无道路走廊越界；触发时实际车端目标像素必须为0而路侧>0；消息可用前不得影响控制。仅车端可能同样成功，必须如实报告，不预设它必定碰撞。

参考分支在碰撞后结束，其他分支至10 s；不补齐或回放另一分支的未来。保存原始合法观测、决策、实际轨迹、碰撞传感器JSON、消息事件、每分支清理报告、源码和配置哈希。相机每0.1 s留原始1280×720 PNG，另存碰撞触发帧；双视角视频为2560×720、10 fps，均来自真实原帧。图片、视频和原始记录放 H 盘原运行目录，中文命名并使用归档脚本复核；Git只保存代码、配置、Markdown和位置/哈希清单。

IDE日常入口是 `scripts/run_occluded_junction.py`，默认无需CLI；先人工启动本机匹配版本的CARLA服务。首次桥接依赖单独按 `configs/runtime/n14_bridge_requirements.txt` 准备，视频组为 `uv sync --group simulation-video`，不会由日常入口自动安装。分析可使用 `--run-dir` 明确指向本次目录；默认选择最近完整三分支运行。所有脚本从文件位置解析仓库根，不依赖启动目录。

修改了共享同步重载入口，因此补跑 N12 同步/清理/IPC单元回归和真实200 tick，以及 N13 执行器回归。失败的可见性位置、运动前缀差异、接入异常和原始图像均保留；本节点结果不能推广成一般避撞成功率或真实交通安全保证。
