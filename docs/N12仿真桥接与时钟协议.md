# N12 仿真桥接与时钟协议

范围为本机独立算法进程与 CARLA 的同步通信、观测过滤和评测旁路；实施与实际验收状态以[节点计划](项目节点实施与验收计划.md#n12-carla桥接同步时钟与真值隔离)为准。用户选择 CARLA 0.9.16，核心与桥接均使用 Python 3.11；选择版本不等于已完成本机客户端与服务端握手。

核心 `scripts/run_carla_bridge.py` 可在 IDE 无必填参数运行；默认本机 127.0.0.1:2000、0.05 s、200 帧、RGB 等待 0.5 s、桥接解释器和产物写入本机 H 盘项目目录。更换电脑时通过可选命令行参数覆盖实际解释器、硬盘目录、地址和端口；路径不依赖启动目录。脚本不下载或启动服务端，缺依赖、连接失败或版本不符必须报错。该入口仅输出安全复核后的静止制动，用于同步实验，不能作为执行器标定或实际避撞效果。

桥接运行于独立 Python 环境，核心不安装或导入 CARLA。双方以本机认证 IPC 传输长度受限的 JSON；核心发 N02 `AdvanceRequest`，runner 按运行、episode、generation、时钟、下一帧、有效期校验并单独持有 World 和推进 tick。桥接返回 N02 `TickEvent` 与按帧白名单校验的 RGB；缺帧有界等待后明确标记 invalid，不使用未来帧补当前帧。同步配置为固定步长 0.05 s、物理子步上限 10、最大子步 0.01 s，完成或异常时尝试只销毁本次 actor 并恢复原设置。若服务端已断开导致无法清理或恢复，必须记录实际失败，不宣称恢复成功。

桥接侧 `truth_logger` 将本次自车位姿写入评测旁路，不通过 IPC 发给在线核心；这不等于已实现完整多目标真值、感知或场景闭环。进程内真实 IPC 模拟服务端夹具只检验通信与隔离机制，不替代实际 CARLA 结果。独立 `scripts/test_n12_carla_cleanup.py` 须用桥接 Python 运行，针对断连、超时和异常注入，旁路对比服务设置及 actor 集合；实际能否通过须以运行报告为准。

每次运行输出配置、握手、逐帧 JSONL、异常请求、桥接日志及评测真值。成功完成时按原始逐帧数据生成中文文件名图表与来源哈希；所有运行产物和过程图保留在移动硬盘，不纳入普通 Git。前期失败、中断日志也保留。已取得真实服务端 200 个连续 tick 和 IPC 断连等故障清理证据；服务端失联实测发生桥接原生进程异常退出，清理与恢复未获证明，本节点自测未通过，详见节点计划。
