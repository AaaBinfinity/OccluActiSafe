## 输入、处理与产物

- 输入：人工取得并登记来源的 TFD 目录。当前硬盘项目目录为 `H:/OccluActiSafeDataset`，TFD 相对路径为 `V2X-Seq-TFD`，SPD 目录为空；盘符可变，运行前须重新核实身份、挂载、空间、写权限和目录。原始数据保持只读，配置与产物不写入原始目录。硬盘内的 `数据集说明.md` 不提交 Git，记录当前真实状态；本次全量运行的证据和结论见节点计划。
- `configs/data/tfd.yaml` 与 `scripts/prepare_data.py`，分别支持 IDE 显式默认配置、脚本覆盖和可选 CLI 的 `--data-root`、`--output-root`、`--scope full`。路径不依赖 cwd，不自动发现移动硬盘、下载或解压数据；缺数据、空目录、无 CSV 和依赖缺失须明确失败。所有数据与大型产物放在硬盘项目目录，审计输出如 `artifacts/data_audit/<run_id>/` 必须位于所选 TFD 原始根之外。默认路径须在重新实施时按实际硬盘配置，不沿用仓库内的旧数据目录。
- `data/adapters/tfd.py`：只读提取原始文件、物理行号、完整原始字段、来源 ID、视角、文件级 episode、类别、位置、速度、尺寸、信号和地图。兼容官方结构及 `train/val/test_obs/data` 嵌套布局，但目录名不能证明官方划分身份。官方未知类别与非法类别分开，不把自行车统一冒充骑行者。时间、位置、速度、航向的单位未证实时保留原值及未确认标记；协同数据的在线因果性未证实时标为离线资料。
- `data/quality.py`：按文件流式处理，每文件内按 ID 和原始时间排序，不跨 ID 求差分，不实施 N04 的划分、滑窗或训练。重复、倒序、缺 ID/时间/坐标、非法类别及不完整行均保存原字段、文件、物理行号和处理原因。原始与有效行、文件级 episode、文件/ID、类别与子类别、缺失字段、原始时间跨度分别统计；报告实际行人和骑行者数量及其分母。跨视角文件/ID 数不得相加冒充独立物理目标数，同一目标类别变化也不能重复冒充独立样本。内存主要取决于单文件大小及全局文件索引，须在实际规模验证。
- `data/tfd_audit.py`：调用 N02 运行清单记录不可变代码版本、来源自报、配置及哈希，生成 run_id。保存识别文件 SHA-256 清单、`data_manifest.json`、`data_quality.json`、`anomalies.jsonl`、`trajectories.jsonl.gz`、`traffic_lights.jsonl.gz`、`map_index.json`、字段字典、抽查原始行及轨迹 SVG。来源、获取日期和 `usage_conditions_claim` 均须区分用户自报与独立证据；只记录公开信息，不保存凭据。`--scope full` 或路径名称不得自动使 `formal_data_ready` 成立。
- 地图单文件读取后保留轻量索引供轨迹与信号复用；缺失、损坏、字段不完整和映射未解析分开记录。不得凭 `yizhuang_hdmapN.json` 与轨迹文件编号猜测关联。轨迹 SVG 仅展示原始轨迹，未验证单位或配准时不能冒充地图叠加图。
- 完整转换轨迹和信号沿用用户确认的 gzip JSONL 设计，每行保留完整 JSON 记录，可用 `gzip.open(path, "rt", encoding="utf-8")` 逐行读取。轨迹、异常、信号分别每10,000行检查输出盘空间，低于10 GiB 时明确失败并保留部分产物；压缩不保证任意数据均放得下，运行前仍须核查空间。失败、中断、完成状态及产物完整性分别记录，部分结果不能标为完整。入口提供 `--workers 1～8`（默认1）；全量运行可有界并发计算哈希、按连续文件区间分片处理轨迹。每文件采用相同质量规则，串行与并行结果须通过一致性测试；gzip 多成员拼接后可直接由 Python gzip 顺序解压。分片与进度保留在 run 的 `shards/` 中，不承诺断点续跑。

## 测试与验收

N03 与 D01 数据审计子范围的全部适用断言仍须按节点计划执行，机制夹具、真实审计和必要的共享模块回归分别报告：

1. 构造重复、倒序、缺 ID/坐标、非法类别、不完整行和多 ID 记录，核对原始定位、完整原值、原因、去重排序及不跨 ID 差分。
2. 对实际 Example 和正式数据分别登记身份、范围、文件/episode/文件-ID、原始与有效分母、类别、时长、缺失与异常；逐项抽查原始行与转换结果、时间单位、坐标、视角来源、地图和信号。未核实项保持未决，样例结果不能外推全量。
3. 缺地图、缺列、损坏和无效输入须显式记录；地图不能凭编号关联，未知单位不能写成已确认米/秒；协同来源匹配不能单独证明在线因果性。
4. 从仓库根、脚本目录和其他目录启动结果一致；缺数据非零退出、指明实际路径且不产生成功报告；导入入口不自动运行。必要回归须在当前机器实际执行，失败、错误、跳过和未执行均不得算通过。
5. 核对硬盘上的运行清单、哈希、质量报告、异常、完整压缩轨迹与信号、地图索引、字段字典、抽查产物和状态；完整数据必需条件满足后才可提交待用户验收。检查 RGB 与二维检测框的实际有无；TFD 轨迹/地图不直接充当 YOLO 图像检测训练集，SPD 实验仍属于 N15 起的后续授权范围。

本版本机制测试、真实审计和 N01/N02 回归分别见节点计划；失败日志保持原样。自测通过仅可记“待用户验收”，不得代填用户验收通过。

## 本机运行方式

默认 `configs/data/tfd.yaml` 明确指向本机 `H:/OccluActiSafeDataset/V2X-Seq-TFD-Example`，输出指向硬盘产物目录；盘符变化须先核对硬盘再修改配置。当前只取得正式数据而未提供该 Example 目录时，默认任务明确失败。IDE 中可设置 `scripts/prepare_data.py` 顶部的 `CONFIG_FILE` 或 `OVERRIDES`，随后无参数点运行。正式数据必须显式设置 `data_root` 和 `dataset_scope: full`；本次实际任务配置位于硬盘 `artifacts/n03_20261029/full_config.yaml`。

可选 CLI：`python scripts/prepare_data.py --config H:/OccluActiSafeDataset/artifacts/n03_20261029/full_config.yaml`。首次安装与数据准备分别执行；该脚本不下载、不解压、不安装依赖。`usage_conditions: verified` 仍是调用方声明，并与 `usage_conditions_note` 及审计器未核验的证据状态一起保存；不能据该字符串自动宣布数据就绪。

单车和单路侧 episode 命名空间包含来源视角；两者同名文件不视为同一次采集。协同文件的共同文件名只是待核查的配对标识，不能直接当作 N04 的独立分组结论。数据中的缺帧与原始时间间隔原样保留。地图匹配只认已定义的明确标识；`yizhuang_hdmapN` 不按编号猜测关联，未解析时如实记录。
