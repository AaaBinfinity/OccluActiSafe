# N03 TFD 数据适配与质量审计

当前状态：代码已实现；用户提供的 TFD-Example 目录已完成一次真实样例审计。正式训练所需数据和使用条件未就绪，N03 仍受阻。测试证据及状态以[节点计划](项目节点实施与验收计划.md)为准；样例审计和构造夹具均不代表正式数据效果或研究结论。

## 来源与使用边界

[AIR-THU 官方数据入口](https://github.com/AIR-THU/DAIR-V2X-Seq#dataset-download)列出 TFD-Example 和完整数据；[官方结构说明](https://github.com/AIR-THU/DAIR-V2X-Seq/blob/main/dataset/v2x-seq-tfd/README.md)描述车端、路侧、协同轨迹、地图及信号字段。2026年10月27日本机对[官方样例链接](https://drive.google.com/file/d/1-Ri92z6rkH14vAOFOx5xhfzvFxBptgAA/view)和[官方公开目录的另一份样例](https://drive.google.com/file/d/1EI_INcDVkcDRlyfcj8PK1cf2JCfDFZyQ/view)的确认下载均曾返回配额超限网页；此后用户提供样例目录。未取得原始压缩包或官方校验值，不将目录名当成独立的来源验证。

[官方完整数据目录](https://drive.google.com/drive/folders/1XnNDS4nV2wrL6dWVc7jLjTD5X2tMdCvt)所列分卷约31.3 GB（压缩后）；未下载或核实解压后空间、正式数据完整性和数据使用条件。维护者的[公开说明](https://docs.google.com/document/d/1PlQyltoo4lLGRGPLx-TmMpzbDaihI-kswzwGWY3YvB8/export?format=txt)称测试部分未发布。未发现明确的 TFD 数据许可条文，不能把代码仓库许可当作数据许可，也不能假称已有官方带标签测试集。取得样例只验证接通；按计划正式训练所需数据也必须登记、适配并审计后才能认定 N03 就绪。

## 输入、输出与步骤

- 输入：人工取得并核实来源的 TFD 目录；默认任务配置为 `configs/data/tfd.yaml`，数据路径为 `data/raw/v2x_seq_tfd/V2X-Seq-TFD-Example`，源码不下载或解压数据。已知数据取得日期可在任务配置填如 `acquired_date: "2026-10-27"`，未知保持 `unknown`；日期和使用条件均为调用方自报，审计程序不将其当作独立证明。CSV 支持官方结构和 `train/val/test_obs/data` 嵌套布局，目录名只标识发现的分组，不能证明官方标签或独立场景。
- `data/adapters/tfd.py` 只读提取原始文件和物理行、来源、视角、文件级 episode 标识、位置、速度、尺寸、类别、信号与地图；保留原始列及来源 ID。`UNKNOWN` 等官方未知类与无效类分开；不把自行车统一冒充骑行者。坐标、航向、速度和时间的实际单位未核实，原值保留，不伪造米/秒；协同轨迹是否使用未来信息尚未知，标为离线、不能直接作为在线可用消息。
- `data/quality.py` 按文件流式处理，每文件内按 ID 和原始时间排序；不跨目标求差分，不实现后续划分、滑窗或训练。重复、倒序、缺 ID/时间/坐标、非法类别及不完整行均记录异常类型、原文件/行、完整原始字段和处理理由；原始与有效的行数、文件级 episode 数、目标数、类别/子类别、缺失字段和原始时间跨度分别报告。相同物理目标跨视角重复出现时，文件/ID 计数不能直接解释为去重后的物理目标数。内存主要受单个文件大小与全局文件索引影响，尚未进行完整集规模压力测试。
- `data/tfd_audit.py` 调用适配和审计，使用 N02 运行清单生成 run ID；保存每个识别文件的 SHA-256、来源和配置、`data_manifest.json`、`data_quality.json`、`anomalies.jsonl`、`trajectories.jsonl.gz`、`traffic_lights.jsonl.gz`、`map_index.json`、字段字典、抽查行和轨迹 SVG。SVG 仅显示原始轨迹，未核实坐标单位与地图配准，不冒充地图叠加图；地图缺失/损坏/字段不完整及映射未解析分开记录。真实样例的 `yizhuang_hdmapN.json` 已逐个索引，但与 `yizhuang#N-...` 的对应关系未凭编号猜测；单文件读取后保留轻量索引供轨迹及信号复用。`usage_conditions_claim` 是配置自报，审计程序不核实法律许可；调用方只应提供公开、不含凭据的元信息。
- 用户于2026年10月28日确认完整轨迹和信号以 gzip JSONL 流式压缩保存；每行仍为原有 JSON 记录，使用 Python `gzip.open(path, "rt", encoding="utf-8")` 逐行读取。该格式改变旧产物文件名，旧未压缩运行仍保留原样。压缩无法保证任意数据均适合现有磁盘；轨迹、异常和信号分别每10,000行检查一次输出盘，剩余空间低于10 GiB时明确失败并保留部分产物，运行前仍应核查可用空间。
- 输出位于 `artifacts/data_audit/<run_id>/`，原始数据目录只读，报告不能写入原始目录。空文件、错误目录和缺少 CSV 明确失败，不自动生成替代数据。`formal_data_ready` 在本实现中保持 false：正式数据的来源、范围、使用条件、单位和划分必须另行核实，不能凭路径或 `--scope full` 标签自动宣布就绪。

## 运行与检查

首次在仓库根执行 `uv sync --locked`。IDE 选择 `.venv` 解释器，打开 `scripts/prepare_data.py` 即可运行，无必填参数；它默认读取已准备的 Example，不自动下载。Windows 入口以 UTF-8 输出错误；本机仅从三个工作目录实测了缺数据负例，未操作 IDE 图形界面。也可通过可选 CLI 指定真实目录：

```sh
uv run --no-sync python scripts/prepare_data.py --data-root /path/to/TFD-Example
uv run --no-sync python scripts/prepare_data.py --scope full --data-root /path/to/verified-full-TFD
uv run --no-sync python -B -m unittest discover -s tests/unit -v
```

数据缺失时入口非零退出并指出路径；有数据后先复核 `data_manifest.json` 的来源和哈希，再抽查原始行与转换结果、时间/坐标单位、视角来源、地图、信号以及行人和骑行者数量。TFD 的轨迹与地图不包含可直接用于 YOLO 检测训练的 RGB 和二维框；是否存在额外文件需按实际包复核。

N03 的测试输入与断言包括：重复/倒序/缺 ID 或坐标/非法类别的原始定位及去重排序；原始和有效分母、类别与子类别统计；缺地图、缺列和无效数据显式标记；不同工作目录运行一致；缺数据不产生成功结果。用户提供的样例包含 404 个轨迹 CSV、162 个信号 CSV、28 个地图 JSON；审计得到 866,695 条原始与有效轨迹行、5 处原始倒序。`cooperative/train/10048` 单场景的协同记录按非缺来源 ID 与同时间戳匹配车端470/470、路端239/239；路端坐标差异已记录，不能仅据此判错，也不能证明在线因果性。

样例单场景的相邻时间值以0.1为主，结合官方 [10 Hz 论文](https://openaccess.thecvf.com/content/CVPR2023/papers/Yu_V2X-Seq_A_Large-Scale_Sequential_Dataset_for_Vehicle-Infrastructure_Cooperative_Perception_and_CVPR_2023_paper.pdf)和[处理代码](https://github.com/AIR-THU/DAIR-V2X-Seq/blob/main/tools/trajectory_fusion/fusion_for_prediction.py)，支持以0.1秒作为该抽查采样间隔；绝对时钟域、地图关联和坐标参考仍未完成核实，程序保留原始单位。样例类别数及失败分析见节点计划，不能外推为完整集规模。
