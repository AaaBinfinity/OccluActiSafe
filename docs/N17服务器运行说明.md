# N17 Windows服务器运行说明

原服务器包为三族n型号、默认30轮。用户随后提供Windows/A100/64GB口述信息并要求全尺寸/早停，当前应使用[N17 A100全尺寸说明](N17A100全尺寸训练说明.md)及`configs/experiments/n17_server_a100.yaml`：15模型、45次正式训练、最多300轮、至少50轮、patience30。下文保留原n包的操作与历史实测，不表示新版A100已经训练。只覆盖N17，不运行N18、不改变原召回/误警/延迟门槛；原三轮结果、失败与last入口保留。

## 1 带哪些文件

在数据所在电脑运行`scripts/package_n17_server.py`，IDE不需要参数。默认输出移动硬盘项目`服务器输入/N17/n17_input_<uuid>/`，包含：

- `data/images`和`data/labels`：固定train/model_val共20,188张图及标签，不带test。
- `data/逐帧数据索引.jsonl`及原数据清单：原字节/原SHA保留；里面的旧H盘地址只作来源。
- `weights`：YOLO26n、YOLOv8n、YOLO11n三份官方初始权重。
- `输入清单.json`：每文件相对路径、大小和SHA。
- `N17服务器代码.zip`：已提交的仓库源码、配置、文档、既有thesis/SVG及`.n17_source_version.json`，不带旧虚拟环境和凭据。

将**整个成功输入包**复制到服务器，再解压其中代码ZIP。不只拷一个入口Python文件。数据盘本机打包优先使用文件硬链接节省空间，跨卷则复制并复核；复制到另一台机器时带走实际文件内容。输入包不是目录联接，不依赖服务器挂载原H盘。失败准备目录保留，选`准备状态.json.status=completed`的包。

也可在服务器Git克隆/拉取本仓库，并单独复制输入包。源码ZIP无需服务器安装Git即可运行；修改受保护源码会被拒绝，不能把改过的代码继续冒充同一版本。

## 2 首次环境准备

需要Python3.11和uv。首次准备可以联网，日常训练不自动安装依赖、下载权重或回退CPU。在解压后的`OccluActiSafe`目录打开PowerShell：

```powershell
.\scripts\run_n17_server.ps1 -Setup
```

它执行`uv sync --locked --python 3.11 --group training --group perception --group simulation-video`，使用项目`.venv`。缺uv时先按提示安装uv；不复制另一台电脑的`.venv`。若PowerShell阻止执行脚本，可直接在仓库根执行上述uv命令及后文Python命令，脚本不修改全局执行策略。

锁定torch2.11.0+cu128、torchvision0.26.0+cu128、Ultralytics8.4.197；实际驱动、GPU架构、CUDA卷积和NMS能否运行由`check`实测。不根据GPU型号猜兼容，不混装CPU torchvision。没有CARLA服务端依赖，使用N15已有图像。

## 3 只需先填站点参数

打开[配置模板](../configs/experiments/n17_server.yaml)，主要修改：

```yaml
input_root: D:/OAS_Input/n17_input_实际UUID
output_root: D:/OAS_Results
device: 0
```

这里的D盘只是填写示例，请换成真实服务器路径。输入目录和结果目录不能嵌套，均须在Git仓库外；相对路径相对仓库根，与启动目录无关。建议使用较短目录。`font_path`默认寻找服务器Windows中文字体，找不到或不含所需中文字形时填写合法`.ttf/.ttc`文件路径；不会自动下载字体。

`device`相对父进程`CUDA_VISIBLE_DEVICES`。启动worker前只暴露选中的卡，worker内部使用逻辑cuda:0，并核对实际GPU UUID。不是忽略用户GPU编号，也不启用多GPU/DDP。默认batch8、workers0、FP32，训练和评测统一；不自动缩小batch，调整站点batch时所有家族共同使用且有效batch相等。

IDE直接运行[Python入口](../scripts/run_n17_server.py)默认`check`；CLI参数全部可选。站点配置可以另存仓库外，使用`--config`/PowerShell的`-Config`指定，避免把服务器私有路径推入Git。GPU、内存、磁盘空闲下限写在配置中，只是预检下限，不承诺不会OOM。

## 4 推荐执行顺序

先预检：

```powershell
.\scripts\run_n17_server.ps1 -Action check
```

预检逐文件核验全部RGB/标签/初始权重SHA，检查Python/依赖/CUDA/GPU空闲资源、GPU NMS/卷积和中文字体。在CPU构造三族目标分类头，验证person→pedestrian兼容分类参数确实复制；这不是训练/召回实验。缺项明确失败，保存错误报告。

可先生成完整计划、核查原生训练参数和数据YAML，**不训练**：

```powershell
.\scripts\run_n17_server.ps1 -Action formal -DryRun
```

然后做短程开发对照：

```powershell
.\scripts\run_n17_server.ps1 -Action pilot
```

pilot为三族×baseline/person_alias两配方×seed17，各默认3轮，6次训练；每配方训练后对3份微调权重执行完整SPD/CARLA模型验证。只改变person→pedestrian名称迁移因素，其余SGD、学习率、warmup等保持共同配方。单seed开发对照不代替正式三seed，不生成正式模型入围结论；`开发配方对照.json`和`结果导航.md`保留各类召回、误检和延迟，不只挑行人一个指标。

审阅pilot后，在配置中选择`formal_policy: baseline`或`person_alias`；模板默认person_alias仅是待检验配方，不表示已经胜出。确认`formal_epochs`、batch和workers等预算后启动：

```powershell
.\scripts\run_n17_server.ps1 -Action formal
```

formal为一个统一配方、三族×seeds17/29/43，共9次GPU训练，默认每次30轮；完成后自动统一评测三份官方预训练及九份微调权重，共12份×3,185帧。按原冻结规则输出`selected`或`no_qualified_candidate`，两者如实保存；不改门槛保证过关。输入原索引为83e945…，原数据/划分不变，迁移后的本地路径索引另有SHA，训练配置/权重/源码/设备独立登记。

按本机旧串行FP32速度，9次×30轮粗略线性估计约53小时，不是服务器实测或耗时承诺，也不保证收敛/达标。当前脚本只落实迁移对照与增加共同轮数，没有实施行人重采样、其他学习率搜索、定位或闭环。需要更多因素时另建预声明对照。

对应Python入口为：

```powershell
.\.venv\Scripts\python.exe scripts/run_n17_server.py --action check
.\.venv\Scripts\python.exe scripts/run_n17_server.py --action pilot
.\.venv\Scripts\python.exe scripts/run_n17_server.py --action formal --dry-run
.\.venv\Scripts\python.exe scripts/run_n17_server.py --action formal
```

只希望IDE点运行时，修改配置中的`action`；默认仍是check，避免误开长训。

## 5 中断与任务级续跑

屏幕会显示每个任务的原控制台内容，并完整保存到该attempt的`控制台.txt`。每次优化更新仍写原始CSV，按epoch写验证JSONL，保存中文PNG/SVG、损失分项、学习率/梯度/耗时/显存、来源SHA及逐epoch检查点。

中断后使用屏幕打印的**同一run绝对路径**：

```powershell
.\scripts\run_n17_server.ps1 -Action formal -Run 'D:\OAS_Results\02_运行产物\n17_server_formal_实际UUID'
```

已完整完成的任务先核验预算、权重/输出SHA再跳过；已中断/失败的**单次训练**新建attempt，从相同官方初始权重重跑，旧CSV、权重和失败完整保留。这里只承诺任务级续跑，**没有实现优化器级/epoch内恢复**。不把旧3轮last直接续训后冒称同一30轮学习率计划。完成后的run仅复核，不改原结果或重复训练。

站点配置、冻结配方、输入、受保护源码或GPU UUID改变时拒绝混入旧run，应新建任务；同一输出/GPU使用OS文件锁防并发，退出自动释放，不结束未知进程。回传后的服务器run用于复核，不在本机假装原服务器环境继续跑。

## 6 看结果并打包回来

结果写在配置的输出目录。完整成功任务自动建立`01_最终结果/last_n17_server_<模式>_<uuid>`目录联接，指向原run；不改原目录名或内部绝对路径。开发pilot入口注明development_only；计划、失败和未完成不会提升为最终last。脚本不修改仓库最终目录总表，回传后再核验登记。

```powershell
.\scripts\run_n17_server.ps1 -Action collect -Run 'D:\OAS_Results\02_运行产物\n17_server_formal_实际UUID'
```

输出`回传包/N17服务器结果_<uuid>.zip`及`.zip.sha256`。包内含配置/环境/任务记录、逐步/逐轮原始记录、全部微调检查点/权重、中文图、逐帧预测/计时、指标及哈希清单；不重复打包输入RGB和官方输入权重。失败任务也能回传，清单明确complete=false，不伪装成功。活动任务受锁保护不能同时打包。

请把ZIP和SHA文件一起带回，并将服务器全部图片/视频/原始CSV/JSON/权重/日志同步回移动盘的本节点/原run目录，继续中文归档；不推普通Git。服务器实测与本机5060Ti结果分列，不能拿服务器速度冒充本机速度。类别零GT、N15遮挡代理/人工抽查/同源未知等限制继续保留。
