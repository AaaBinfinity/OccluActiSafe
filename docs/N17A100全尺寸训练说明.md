## 1 模型与共同预算

三族的检测模型均有n/s/m/l/x尺寸，来源为[YOLO26官方说明](https://docs.ultralytics.com/models/yolo26/)、[YOLOv8官方说明](https://docs.ultralytics.com/models/yolov8/)及[YOLO11官方说明](https://docs.ultralytics.com/models/yolo11/)。本次保留n作为同预算参照，包含全部s/m/l/x，共15种；不从COCO公开精度推定本项目赢家。

| 项目 | 新全尺寸配置 |
| --- | --- |
| 模型 | YOLO26n/s/m/l/x、YOLOv8n/s/m/l/x、YOLO11n/s/m/l/x |
| 正式种子/次数 | seeds17/29/43；15×3＝45次串行GPU训练 |
| 每次共同预算 | 最多300epoch、至少50epoch，model_val原生fitness连续30epoch无严格改善后允许早停 |
| 检查点 | 所有正式候选统一评model_val原生best.pt；last及中间检查点、失败完整保留 |
| 精度/输入 | 全部AMP训练、batch/nbs16、workers4、最长边960、cache=false；最终统一评测仍FP32/batch1 |
| 数据 | 同一冻结train17,003张/model_val3,185张、三类有GT、另两类零GT；不打开test |
| 优化器 | 原共同SGD/lr0=.001/lrf=.1/momentum=.937等保持；不增加重采样或额外HPO |
| 正式评测 | 15官方预训练＋45微调best，共60权重×3,185帧，按型号/阶段/seed完整分表 |
| 开发对照pilot | 15种×baseline/person_alias×seed17，各3epoch，共30次；不早停、不选正式部署模型 |

最大300轮与50/30早停规则是本项目此次预声明的共同预算，不是已测得的“可收敛轮数”。触发平台期只说明该指标满足规则，达到上限也不说明收敛或达标。零fitness沿锁定框架规则更新基准，可能一直跑到上限；NaN/失败不能记成正常早停。官方patience定义见[训练参数](https://docs.ultralytics.com/modes/train/)，具体实现以锁定8.4.197与本项目重放测试为准。

只使用model_val选择best与早停，不读取test。每族每尺寸的三个seed均须完整达到自身的上限或有可重放的早停证明；不能挑一个好seed。新矩阵的AMP、检查点策略及预算与旧本机三轮不同，两批分开报告，不拼接最好结果。A100的评测速度不能替代5060Ti上的部署时延。

## 2 操作步骤

复制完整便携输入包，使用其中新增`N17_A100服务器代码.zip`，保留旧`N17服务器代码.zip`供追溯。新版完整数据包还含`扩展权重`的15份官方权重；旧`data`、`weights`和`输入清单.json`原字节不改。新增12份权重的下载与哈希仅属于N17，不下载其他模型或test。

解压新ZIP，在代码根PowerShell操作。首先修改[全尺寸配置](../configs/experiments/n17_server_a100.yaml)中的input_root/output_root/device。输入、输出均须在Git外且互不嵌套；weights_root留空默认输入包/扩展权重：

```powershell
$cfg = 'configs/experiments/n17_server_a100.yaml'
.\scripts\run_n17_server.ps1 -Setup
.\scripts\run_n17_server.ps1 -Config $cfg -Action prepare-weights
.\scripts\run_n17_server.ps1 -Config $cfg -Action check
.\scripts\run_n17_server.ps1 -Config $cfg -Action estimate
.\scripts\run_n17_server.ps1 -Config $cfg -Action pilot
```

prepare-weights仅显式准备时允许下载，固定官方assets v8.4.0和逐文件SHA；15份齐全时只核验，不重下，不覆盖错误文件。下载失败保留part及准备记录，重试保留原失败。日常check/train不自动下载，不回退CPU、不自动减batch。当前模型初始权重总779,695,599 bytes，固定SHA来自[官方发布元数据](https://api.github.com/repos/ultralytics/assets/releases/tags/v8.4.0)，资产表在`detector_models.py`；三份旧n初始SHA不变。

pilot完整结束后会输出`正式训练耗时外推/耗时预算.md/.json`。先看两配方各类别召回、误检和延迟，再明确formal_policy（模板person_alias仍是待验证配方）。正式运行：

```powershell
.\scripts\run_n17_server.ps1 -Config $cfg -Action formal -DryRun
.\scripts\run_n17_server.ps1 -Config $cfg -Action formal
```

IDE可直接运行`scripts/run_n17_a100.py`，默认只check，无必填CLI；CLI `--action`可覆盖。原`run_n17_server.py`与旧配置默认仍为三族n，不能省略全尺寸配置后误以为已跑15种。

NVIDIA官方A100标准规格为40GB/80GB，见[NVIDIA规格](https://www.nvidia.com/content/dam/en-zz/Solutions/Data-Center/a100/pdf/a100-80gb-datasheet-update-nvidia-us-1521051-r2-web.pdf)。用户提供64GB在此仅作口述资源信息，不猜测是配额、可用显存或系统RAM；check记录真实名称、GPU UUID、总量/空闲量与驱动。全尺寸模板要求名称含A100、空闲显存≥24GiB、可用系统RAM≥16GiB、输出空闲≥500GiB。这些只是预检下限，不能保证最大模型batch16不OOM；缺项明确失败留证。需调低batch时所有15种共同改、新建run，不拿各模型不同自动batch混比。

## 3 时间估算与实测修正

没有A100实测，不能由显存或公开TensorRT推理速度算出训练时间。以下仅为单卡串行、960/batch16/AMP、含训练/验证/输出的条件假设：n每轮1～2.5分钟、s 1.5～3.5、m 2.5～5.5、l 3.5～7.5、x 5～11；不是官方基准或本项目已测吞吐。

| 假设45次各自实际轮数 | 总时长情景（含10%最终评测/输出余量） |
| --- | --- |
| 全部50轮 | 约111～248小时，即4.6～10.3天 |
| 平均100轮 | 约223～495小时，即9.3～20.6天 |
| 全部跑满300轮 | 约668～1,485小时，即27.8～61.9天 |

公式：`总秒数＝Σ每型号每轮秒数×3seed×假设实际轮数×1.1`。早停轮数目前未知，表中100轮不是收敛预测；实际可能在表外。首次Setup、数据传输/下载和30次pilot另计；按同一假设，pilot约4～10小时，仍需实测。输出磁盘、CPU解码/Windows杀毒、GPU共享/MIG、检查点写入和验证都可能改变时间，10%余量不是严格上界或统计置信区间。

pilot记录每轮原生墙钟耗时（含验证与保存）；至少3轮时只在外推中排除首轮，原值全部保留。按所选配方逐型号取其余轮均值，外推区间为该均值×[.8,1.3]再按上式计算，保存15个独立计时源与SHA，不用n代填x。该区间是资源规划假设，不是统计置信区间。若CPU、磁盘或正式配置改变，须重测；不把5060Ti实测冒充A100。可用`-Action estimate -Run '<已完成pilot绝对路径>'`重新生成，同站点配置、完整模型计时缺一即拒绝。

## 4 早停、留证与回传

`PlateauStopper`逐epoch记录fitness、best_fitness、首次严格改善的best_epoch、无改善轮数、最少轮数、patience及stop。审计独立重放每条记录，核对逐轮原生fitness、逐轮SHA、每轮实际更新/样本曝光及best/last权重；不足预算而没有早停证明会失败，不能把原来“必须跑满”的审计简单关闭。

所有优化更新原始CSV、逐epoch验证/耗时JSONL、早停原始JSONL、中文PNG/SVG和来源SHA保留。训练精度与请求不一致（包括原生AMP检查回退）即拒绝混比。正式中间checkpoint采用原生save_period=10（框架零基epoch0/10/20…，即第1/11/21…轮），最终best和last都保留；不删除旧epoch检查点。节点三类门槛保持原值，最大模型也须实测通过，不能因参数大而指定赢家。

任务级续跑、失败attempt保留、最后结果last_入口及collect回传沿用[通用服务器说明](N17服务器运行说明.md)。配置/源码/输入/GPU变更不混入同一run；不提供优化器/epoch内恢复。正式任务中断后重试某模型可能重跑该次训练，安排服务器稳定会话；只终止本脚本拥有的worker，不关闭未知进程。

新图、逐帧预测、权重及大型日志存服务器输出，带回移动硬盘原N17/run/seed目录中文归档，不入Git。实际服务器训练尚未执行，不存在可交付的新收敛曲线或新达标模型；具体本机检查、代码版本和证据回填节点计划N17。
