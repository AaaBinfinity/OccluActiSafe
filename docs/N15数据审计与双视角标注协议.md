# N15 数据审计与双视角标注协议

**当前结论（2026-11-01）：** N15主要数据/像素完整性检查已运行。用户明确回复“验收通过继续需执行下一个节点”，据此记录用户验收通过并授权N16；N15自测不通过的原结论、CARLA可见率代理不能代表物体轮廓真实遮挡率、SPD 48张分层图仅人工检查2层/27帧、TFD/SPD精确录制重叠未知等限制均保留。不得据本节点数据声称已完成检测训练、视频感知闭环或独立跨数据集泛化。

## 1. 实施边界与环境

本节点覆盖正式 V2X-Seq SPD 的只读审计和分组，以及 CARLA 0.9.16 中车端/固定路侧双视角同步RGB与实例掩码采集、由实例像素生成可见二维框及离线抽查。不实施检测器训练、模型选择、视频闭环或N16适配。

在 Windows 11 专业版 10.0.26300、PowerShell 7.6.5、项目 Python 3.11.18 和 CARLA 客户端/服务端 0.9.16 实际运行。项目环境使用 NumPy 2.4.6、PyYAML 6.0.3、Pillow（版本见运行manifest）；GPU为 RTX 5060 Ti 16GB，CARLA渲染使用GPU但本节点无模型训练。SPD正式数据只读位于移动硬盘；运行结果与图片均保存在硬盘 `artifacts/节点资料/N15_CARLA双视角标注与SPD审计/`。

## 2. 代码接口

| 接口 | 输入与输出 | 实现与约束 |
| --- | --- | --- |
| `audit_spd(root, seed, verify_image_decode)` | SPD根目录；返回文件、图像、标注、标定、帧配对、位置、类别、质量问题、分层样本与地理split报告 | 逐项哈希、检查RGB解码和索引引用；原始数据只读。版本/许可未由机器证据核验时保留unknown/unverified |
| `build_spd_split(records, seed)` / `audit_spd_split(manifest)` | 序列/路口记录；输出train/model_val/test角色及交集审计 | 以路口地理组隔离，派生双视角/重叠窗口继承组；角色都非空且泄漏数为0才满足结构检查，不代表样本量充分 |
| `resolve_missing_vehicle_locations(...)` | 缺失位置记录与官方车路配对资料；返回可追溯解析结果与未解析项 | 仅采用官方配对证据修复索引映射，不改源数据；未解决项显式计数 |
| `normalize_visible_box(label, width, height)` | 官方可见框、原图尺寸；输出边界内可见框及质量状态 | 只对浮点边界舍入误差做保守裁切；保留源坐标及问题标记，不将3D框投影冒充可见GT |
| `extract_visible_instances(mask_rgb, actor_catalog, projected_actor_boxes=...)` | 同帧实例分割RGB图、actor目录及离线投影参考框；输出正像素实例的可见框、类别、ID、可见像素数和遮挡代理分箱 | 检测可见框只由实例像素最小/最大坐标生成。投影3D bbox仅为代理分母，不作为可见GT；代理受三维盒与真实轮廓形状差异影响。零像素actor仍无法区分完全遮挡与画外 |
| `project_world_points_to_image(...)` / `actor_projected_boxes(...)` | CARLA包围盒世界顶点、相机逆变换、图像尺寸与FOV；输出裁剪参考框或unknown | 相机坐标前向深度须为正；点跨越相机平面或无有效图像交集时不估计。仅用于遮挡代理，不能供检测器/控制器输入 |
| `scripts/audit_spd.py` 的 `run()` | YAML默认配置；IDE可直接运行，也可通过可选CLI覆盖数据/产物路径 | 输出冻结配置、完整审计、split、摘要、manifest及中文分层叠加联系表；产物位置必须在数据硬盘artifacts内 |
| `scripts/capture_n15_carla.py` 的 `run()` | `configs/data/carla_perception.yaml`；连接CARLA 0.9.16 | 同步步进采集1920×1080车端/路侧RGB、实例掩码和标签；每场景帧数、地图/天气、目标类型/速度由冻结配置控制，失败场景留下记录 |
| `scripts/verify_n15_carla.py` 的 `audit_run()` | CARLA运行manifest、双侧RGB/掩码/标签 | 核对frame/time同步、文件SHA、图像尺寸、标签框与掩码像素边界；生成高分辨率双视角抽查图和逐序列联系表。验证完整性不量化遮挡度 |

主要配置为 `configs/data/spd.yaml` 与 `configs/data/carla_perception.yaml`。Python入口均不要求CLI参数，路径由脚本/配置解析而非当前工作目录决定。完整参数值及其哈希以硬盘运行副本为准。

## 3. 规格夹具与断言

SPD测试使用三条互斥原始序列夹具验证三分组非空；将一个序列双视角/重叠窗口拆到不同角色必须拒绝并定位冲突。边界框夹具覆盖越界、浮点舍入、负数尺寸及原记录保留；官方配对解析夹具核对空缺位置映射唯一性。测试不替代真实数据审计。

CARLA机制夹具使用编码实例ID像素块核对类别/track ID、正像素框边界、遮挡代理分箱、空掩码及不可投影情况；数值投影夹具用已知相机坐标点核对像素框。真实数据复核逐文件比较RGB、mask、label与frame/time，并逐像素重算所有可见框；不得通过构造样本替代真实采集。

下一节点检测/跟踪评测口径：分类召回的分母是冻结清单内、按可见语义可评估的GT目标数，按类别/摄像头侧/目标框像素尺度/官方SPD遮挡等级分别报告；漏检不从分母剔除。误警同时报每图FP数及空目标帧误警率，分母为实际评测视角帧数。定位报原图像素xyxy IoU及中心点误差分布，不用网络缩放坐标。端到端检测时延含预处理、推理、后处理，跟踪另报；GPU计时同步，报告p50/p95/最大值、超预算帧数和峰值显存，CARLA与SPD分域。所有门槛只能在N17模型验证数据开封前结合N13控制距离冻结，测试集不调参。该协议定义了指标和分母；具体最低召回、误警、定位和时延门槛尚未数值冻结。
