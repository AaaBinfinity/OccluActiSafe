# N17本机训练吞吐优化

2026-11-04用户要求“优化训练配置”。本次只优化本机N17吞吐、记录和使用配置，不扩大为新的精度搜索或后续节点，不降低原召回/误警/延迟门槛。原六项学习率结果及其源码、权重、清单保持。

## 范围、方法与停止位置

保留960、AMP、SGD学习率、数据/增广、完整逐步/逐轮原值和图集、weights仅last.pt/best.pt、最大300/最少50/patience30。新增独立[n17_local_fast.py](../configs/experiments/n17_local_fast.py)，默认check，不覆盖用户已编辑的n17_local.py，不在本次启动正式长训。

先冻结4个真实性能工况，均为YOLO26n/seed17、同一批512张真实train和96张model_val、每项1epoch：batch2/workers0/CPU14，batch8/workers0/CPU14，batch8/workers1/CPU4，batch16/workers1/CPU4。训练曝光上限2,048；没有自动重试，失败保留，不增加工况。CPU/读图配置只按吞吐和资源选，不用验证精度调参。采样在看模型输出前按冻结索引等距选取，test始终不打开；短程权重仅用于开发联调，不作部署或新精度结论。

每工况沿用真实训练、完整原值/图集和双权重，另记录训练段墙钟、批次原值、前两批热身后的吞吐、主机间隙、GPU计算段、父子进程RSS、系统可用RAM，以及每秒显卡利用率/显存/功耗/温度。主机间隙包含读图、增强和批次间开销，不能冒称纯磁盘IO；不以任务管理器3D图代替CUDA测速。选择成功且至少保留1.5GiB系统RAM、显卡总占用不超过14GiB的工况；只承诺实际测试的型号和输入规模，正式长训及其他型号容量不据此算通过。

## 实现与兼容

`detector_local.local_options`增加可选CPU_THREADS，旧配置缺省0保留框架默认；新值和实际batch等进入冻结配方，恢复须同配方/源码/GPU，不能用新配置接续旧冻结训练。`rich_trainer_class`只在显式配置时设置主进程线程，保存训练/验证loader实际batch、workers、prefetch、pin_memory与内存快照；仍完整记录所有实际更新及AMP跳步，没有删减同步计时、图片或原值。

大batch下probe/smoke按真实输入扩展到至少三批训练/验证样例，旧batch2仍32训练/16验证；数据不足明确失败，不重复或构造图片凑图。锁定Ultralytics 8.4.197的验证loader使用2倍workers，16GB RAM不直接套用8个进程，不启用RAM图像缓存。实际行为以本机安装源码为准；通用参数说明见[Ultralytics训练文档](https://docs.ultralytics.com/modes/train/)，Windows多进程和内存限制见[PyTorch DataLoader](https://docs.pytorch.org/docs/stable/data.html)。

## 运行与验证

IDE直接运行n17_local_fast.py默认只check，改MODEL/SEED/ACTION再运行新任务；CLI可选`python scripts/train_n17_local.py --config configs/experiments/n17_local_fast.py --action plan`。调整型号后须重新核实batch容量；代码内按尺寸列出的保守起点不代表大模型实测。当前性能工况执行脚本及原始证据位于硬盘N17/03_验收证据/n17_performance_20261104，默认只显示计划，显式run才测速。

必需检查：旧配置缺省/新线程范围与配方隔离、至少三批样例的真实分母、原N17及受影响N16回归；4个实际CUDA工况的预算/逐步图集/双权重/来源SHA与资源采样；选定配置异地cwd只计划和默认只检查；旧证据/用户配置保持、图归档/最终入口/文档检查。失败候选与软件检查分列，不以短测速精度证明召回改善。

## 首轮实测与必要内存修复

四项固定工况已原样执行，未自动重试：batch2/0/14与8/0/14均完成512曝光，稳态采样训练段吞吐16.07/32.97张每秒，但原生验证阶段可用RAM最低1,461.58/1,331.87MiB，均未满足1.5GiB余量，不升为最终配置。worker1两项分别在实际112/48曝光时触发1GiB保护而停止，回调已完成图像104/32不能代替训练CSV的真实分母。原四项累计1,184曝光，全部失败/原值保留。

为完成已授权优化所需的内存修复，另冻结一次相同512 train/96 model_val、batch8/workers0/CPU14、原生VALIDATION_BATCH=4的代码修复复核；原四项清单/条件/结果不改，没有自动重试或精度搜索。累计曝光上限仍2,048，本次复核后预期实际1,696，余352不使用；本机正式长训不启动。保持至少1.5GiB RAM及显卡总占用≤14GiB门槛，不为通过降低标准。

可选VALIDATION_BATCH缺省0保持旧原生行为；正值只限制epoch/best原生验证batch，训练batch和N16/N17统一FP32/batch1评分不改。验证batch参与新配方哈希，禁止与旧配置混续或混算精度；在标签绘图后、验证与最终验证前显式gc.collect，保留全部图表/指标和双权重，不以删图减内存。新增配置仍默认check，修复复核满足原资源门槛后才冻结实际推荐值。

实际数值、被测提交、环境/输入/权重哈希、run_id、失败和四类测试数量收尾回填同一[节点计划N17](项目节点实施与验收计划.md)，完成后停N17待用户验收。
