2026-11-04当前使用补强：[独立吞吐配置](N17本机训练吞吐优化.md)已实测YOLO26n/17短程约2.03倍吞吐，采用batch8/workers0/CPU14/原生验证batch≤4及独立预检，仍完整留证/双权重/300上限早停；默认只check，不改用户原选项。原seed17/29均已完成50轮，seed17固定操作点车辆/行人/骑行召回78.17%/22.02%/62.38%仍未达；历史评估见[seed17报告](N17本机YOLO26n种子17训练评估.md)。吞吐优化不证明召回改善，完整长训与其他型号容量未测。

用户要求改回5060Ti16GB/系统内存16GB本机，按参考YOLO目录保留只多不少的记录与图片；当前在终端选择一个模型、seed、学习率和操作，上限300轮并早停，训练输出weights仅last.pt/best.pt。本入口只覆盖N17，不启动N18；旧数据、训练及服务器交付证据保留。

## 1 在终端选择本次任务

直接运行，无须每次修改MODEL/SEED/ACTION：

```powershell
.\.venv\Scripts\python.exe .\scripts\train_n17_local.py
```

菜单依次选择15种型号、seed、SGD学习率lr0、batch和check/plan/probe/train/resume；显示摘要后输入y执行。操作默认check，q/EOF/Ctrl+C或空确认取消。当前脚本默认使用[优化配置](../configs/experiments/n17_local_fast.py)，n/s/m/l/x的batch起点16/4/2/1/1，训练worker1/预取1/CPU4/验证worker0及batch上限4；单worker已用YOLOv8n短测验证，其余型号须先probe检查容量。原[用户选项](../configs/experiments/n17_local.py)保留且可显式指定，不再要求日常编辑；选择及来源哈希另存硬盘。完整用法与真实验证见[终端交互说明](N17终端交互训练说明.md)。

MODEL支持YOLO26n/s/m/l/x、YOLOv8n/s/m/l/x、YOLO11n/s/m/l/x，共15种。一个任务只训练指定的一种和一个seed，结束即停，不自动启动其他模型/seed。正式比较建议分别完成17/29/43，其他合法seed可以训练但另行标记；单次训练完成不代表三seed/全族正式比较或模型达标。

可以直接在IDE运行这个选项Python文件，也可运行[scripts/train_n17_local.py](../scripts/train_n17_local.py)，CLI全部可选、路径不依赖cwd：

```powershell
.\.venv\Scripts\python.exe scripts/train_n17_local.py --action check
.\.venv\Scripts\python.exe scripts/train_n17_local.py --action plan --model YOLO11m --seed 43
.\.venv\Scripts\python.exe scripts/train_n17_local.py --action train --model YOLOv8s --seed 29
```

默认MAX_EPOCHS=300、MIN_EPOCHS=50、PATIENCE=30、AMP=True、workers=0、最长边960、cache=False；batch/nbs由本次实际选择冻结，原历史配置为2，不能把不同batch的任务当同配方对照。最大轮数不能超过300；完成至少50轮后，原生model_val fitness连续30轮无严格改善则早停。早停不保证收敛。各模型正式比较使用共同预算与明确配方。可修改的参数独立于受保护算法源码，每次冻结有效配置、原选项与哈希；选模型/seed不要求先提交Git。选项执行、哈希、归档来自同一字节快照，任务开始后编辑下一次选项不串改当前任务；预检后受保护源码改变则拒绝启动。代码/输入改变与普通参数更改分别留证。

默认输入指向已核验的H盘原便携包，权重在其中扩展权重；图片和记录写原N17硬盘目录。换盘符先核实实际磁盘，再改INPUT_ROOT/OUTPUT_ROOT。只使用train/model_val，不打开test；缺输入、权重、CUDA或资源明确失败，不自动下载、回退CPU或缩batch。首次环境沿用仓库锁定Python3.11/.venv；本入口不自动安装依赖。

## 2 一次任务保存在哪里

正式任务在N17的02_运行产物，probe/smoke在04_开发与复核/本机短程联调，plan在04_开发与复核/本机任务计划。每次新建唯一run_id，不覆盖上一次：

```text
n17_local_<型号>_seed<种子>_<uuid>/
  本机训练任务.json             # 有效模型、seed、配置SHA、版本、GPU及恢复来源
  本次代码选项.py               # 只读参数快照，日常编辑仓库中的原选项文件
  本次训练配置.yaml
  冻结数据元信息/               # 原索引身份+本机路径索引，不复制RGB
  控制台.txt
  结果导航.md
  YOLOv8s/seed_29/训练/
    weights/
      last.pt
      best.pt
    args.yaml
    超参数.yaml
    运行选项.yaml
    results.csv
    逐批次优化尝试.csv
    逐步优化指标.csv
    逐轮验证指标.jsonl
    逐轮分类验证指标.jsonl
    逐轮验证原值/
    逐步原值分页/
    误检漏检与检测样例/
    各类中文PNG/SVG/JPG与来源JSON
```

last是最近完整epoch的可恢复状态，best按model_val原生fitness选择；两者都可由锁定版本的YOLO加载。last还保留优化器、学习率调度器、AMP scaler、FP32原训练模型/EMA、早停及随机状态，不额外生成epoch*.pt。两个文件可能来自相同或不同epoch。首次完整epoch前失败可能尚无权重，不能把这类任务记为完成。历史任务已有的周期检查点不删除。

只有本次正式单模型任务完整通过记录/权重核验才创建last_入口；开发联调、计划或失败不提升为正式训练最终版。last不等于用户验收、准入通过或完整模型选择；后续助手收尾再把真实正式run纳入Git中的总目录表。代码/Markdown入Git，原始数据、图、日志和权重继续只留硬盘。

## 3 与参考图逐项对应

当前锁定框架部分文件名与旧YOLO版本不同；保留实际原生内容并中文归位，另做可复核的补充图，不用虚构指标填满文件夹。

| --- | --- |

| labels、labels_correlogram | 原生标签图JPG及同像素PNG；全部标注类别计数、归一化xywh原始NPZ、类别柱状图、4×4几何相关直方图PNG/SVG |
| confusion_matrix | 原生计数/归一化图，另从实际原生矩阵保存原始JSON与PNG/SVG，标明真实阈值 |
| F1、P、R、PR | 原生图及从实际原生曲线x/y重绘的中文PNG/SVG；逐轮原值JSON与最佳权重验证原值 |
| train_batch0/1/2 | 实际起始前三批训练预处理画面，中文JPG原件及PNG，逐批输入文件/epoch/augmentation来源 |
| val_batch0/1/2 labels/pred | 最佳权重验证前三批真实标签/实际预测，中文JPG及PNG，输入帧和验证阶段来源 |
| 额外优化记录 | 每次实际参数更新的loss/全部分项、裁剪前梯度L2范数、各组学习率、耗时、GPU分配/保留MiB、进程RSS MiB、图像/目标分母与文件列表 |
| 额外资源与停止图 | 逐轮实际耗时、分类验证、AMP更新/跳步及曝光分母、早停fitness/最佳值/耐心线、每轮结束时GPU温度/功耗/利用率采样 |
| 额外预测诊断 | 最佳权重predictions.json、固定score≥.25/IoU=.5的全验证帧TP/FP/FN表、最多12张误检漏检/成功示例及原图/权重/配置SHA |

训练照片保留JPG原件，PNG由同一实际画面无额外有损编码生成；PNG/SVG曲线是同一原始数据的两种格式，不当作不同实验。诊断叠加保持原图像素坐标，底部另加说明栏；不把放大图当原生高清。各图标明模型/seed/run及开发联调属性，原生图来源另由清单追溯。

逐步图每页最多20,000个原始更新点，全部点均保留、分组输出，避免数百万行一次性装入Python大列表。每epoch单独验证，不伪造每step验证指标；loss是监督目标损失，不冒称米制误差或风险概率。原生图若包含框架辅助平滑线，仍有完整CSV和未再次平滑的分页原值图，不能只凭平滑线作结论。训练中持续写原始表，正常结束/显式暂停/可捕获异常时生成图集；强制断电可能来不及绘制最后部分，但已提交原始记录不删除。

原生F1/P/R/PR使用框架统计/插值定义，原生混淆矩阵的conf与匹配IoU在其原值JSON和自绘图中明确；与固定.25/.5的错误样例分开，不把它们冒充N16操作点同一指标。SPD/CARLA非COCO数据的预测JSON用于留证，不触发可选COCO评分，也不保留未实测small/medium/large的占位零。无GT/不可估计类别保留真实GT计数和null/理由，不捏造召回。

## 4 AMP、恢复与中断

AMP初期可能缩小scale并跳过参数更新，逐批次尝试表如实记录；只有实际应用的更新进入逐步优化表。原生EMA顺序、实际更新数、尝试数和图像曝光分别保存，不能把跳步算一次优化更新。非有限损失、FP32非有限梯度、整轮无更新或OOM都失败留证，不伪装成正常早停。

想在某轮结束后暂停，可设置PAUSE_AFTER_EPOCH，例如10，保留300轮总计划；权重和本轮原始记录写完后退出。恢复时在终端选相同MODEL/SEED/学习率/batch及resume，填写原中断任务根目录；仍须满足同配方/源码/GPU等约束，本次新源码不能绕过旧冻结任务的恢复保护。CLI等价：

```powershell
.\.venv\Scripts\python.exe scripts/train_n17_local.py --action resume --model YOLOv8s --seed 29 --run 'H:\实际原中断任务目录'
```

恢复只接受同模型/seed、数据/训练配方、受保护源码和GPU身份。原生epoch边界恢复优化器、学习率、AMP、FP32模型/EMA与随机状态，并在新run中继续原全局步号/早停历史；旧目录、完整失败尾部和图片原字节不改。恢复只携带已提交epoch的原始前缀，未保存的半轮留原目录并重跑。不能承诺任意驱动、数据加载并行度或系统环境下逐位等同从未中断的数据流。

检查点已到上限或已触发早停时不再增加epoch；源码/配方变更需要新任务，不能把旧三轮last拼成同一300轮计划。已有不同目标文件不强制覆盖、不关闭未知进程；同输出/GPU任务由OS锁防并发。原子发布若在last/best间中断，按事务SHA核对可恢复来源，并在新目录恢复，不篡改旧失败目录。

## 5 真实验证边界

默认check不会启动长训，plan只生成本次配置；probe使用预声明的真实开发小样本一轮，smoke为两轮，均标development_only，不进正式比较。小样本固定为SPD/CARLA每域train16张、model_val8张，共train32/model_val16；按可用三类GT做预声明覆盖后按原清单补足，不看模型结果选容易样本。原全量训练仍为17,003/3,185张，test封存。

本次软件交付验证、不可变代码、实际环境、GPU暂停/恢复联调、图片归档、失败及证据回填同一节点计划N17。单次小样本指标只证明管线跑通，不能代替真实全量300轮训练、三seed比较、准入达标或闭环收益；N15数据适用限制继续保留，N18未授权。

交付代码为`8788ef1`；55项N17机制和13项受影响N16回归通过、失败/跳过/未执行均0。真实GPU训练核心在`f64a887`完成YOLOv8n/seed17暂停续训，后续8788ef1只补选项快照及源码身份检查、未改训练/绘图算法。暂停后在新run恢复到第2轮，累计64图像曝光、32批次尝试、25次真实更新、7次原生AMP跳步；最佳验证16帧/70GT，不参与原正式选型。最终run为`n17_local_yolov8n_seed17_3cd765c0731f486892faa5152be3d11e`，同名训练目录下79份图片/矢量图；两份权重各44,577,712 bytes，原生YOLO加载及CUDA推理通过，旧中断目录74个文件SHA保持。

真实样例在硬盘N17的`04_开发与复核/本机短程联调/<上述run>/YOLOv8n/seed_17/训练`，交付证据在`03_验收证据/n17_local_delivery_20261102`。只对YOLOv8n做了该GPU管线联调，其他型号能选择不等于已验证本机显存容量。正式300轮、三seed及全部尺寸训练均未启动，原0/6入围结果不变。启动前可先将ACTION='probe'实测本次型号资源，再按共同配方决定正式任务，OOM保留失败，不自动降低输入或batch冒充等预算比较。
