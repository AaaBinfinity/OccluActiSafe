## 2 场景与系统角色

依据：[研究方案](毕业设计研究方案.md)、[算法成品与盲区鬼探头方案](算法成品与盲区鬼探头方案.md)。

### 2.1 项目名（OccluActiSafe）

- **英文与含义：** 项目说明为 Occlusion-Aware Active Safety for Cooperative Driving；名称表达遮挡环境中的协同主动安全，Python 包标识为 `occluactisafe`。
- **本项目用途：** 统称数据处理、感知、预测、风险与控制算法及验证材料；核心交付是可无界面运行的算法包。
- **易混点：** 项目名、中文论文题目和 RC-STGT 模型名分属不同层级；CARLA 与网页是验证和展示载体。

### 2.2 超视野与遮挡（Beyond Line of Sight / Occlusion）

- **英文与含义：** 超出本车当前直接可观测范围；遮挡是建筑、车辆等阻断视线的具体原因之一。
- **本项目用途：** 例如本车驶近路口时看不到建筑后的横向来车，但路侧摄像头能提前看到并发送观测。
- **易混点：** 路侧也看不到时，系统只能表达未知区域和不确定性，不能凭“超视野算法”获得隐藏目标的真实位置。

### 2.3 鬼探头（Sudden Emergence from Occlusion）

- **英文与含义：** 本项目指行人或骑行者从停放车、大车、建筑等遮挡后突然进入冲突区域；英文是描述性表达，并非统一模型名称。
- **本项目用途：** 检验路侧提前发现、短历史预测、及时制动和无人出现对照；行人与骑行者均在必做场景中。
- **易混点：** 它包含遮挡、发现时机和运动突发性，不能仅靠给检测器增加 person 类别就算完成。

### 2.4 车路协同与协同感知（Vehicle-Infrastructure Cooperation / Cooperative Perception）

- **英文与含义：** 车端与路侧共享信息；协同感知具体指利用多侧观测，改善对环境和目标的认识。
- **本项目用途：** 路侧补充本车盲区，车端结合本地观测复核消息，形成更完整的可用交通状态。
- **易混点：** 共享了信息不等于路侧接管车辆；共享重复来源信息还可能导致重复计数，需要记录来源链。

### 2.5 协同避让与意图协调（Cooperative Avoidance / Intent Coordination）

- **英文与含义：** 多辆可控车辆交换拟采取动作及确认信息，协调各自运动。
- **本项目用途：** E02 条件扩展拟使用 proposal、ACK、commit、timeout 等状态表达提议、确认、执行约定与超时。
- **易混点：** 路侧向一辆车发目标位置属于协同感知；两车协调动作才属于这里的协同避让。扩展需要单独授权。

### 2.6 主车与交通参与者（Ego Vehicle / Agent）

- **英文与含义：** Ego 是本次正在研究和控制的车辆；agent 是参与交通运动的车辆、行人或骑行者等对象。
- **本项目用途：** 主车选择制动或转向，周围目标作为预测、风险评估和避让对象；类别决定尺寸和运动约束。
- **易混点：** 此处 agent 是交通对象或工程模块名称，不能自动理解为大语言模型智能体；目标也不都遵循汽车动力学。

### 2.7 路侧边缘计算（RoadsideEdge / Edge Computing）

- **英文与含义：** 靠近路侧传感器的处理模块，负责把观测变成可共享的交通信息。
- **本项目用途：** 设计职责包括检测、跟踪、米制定位、融合与协同轨迹预测，主链输出目标状态及预测轨迹，并保留各自时间、来源和质量；V端负责最终风险和动作。
- **易混点：** 摄像头、边缘计算器和无线通信单元是不同角色；逻辑上分成路侧与车端，不代表已经部署物理设备。

### 2.8 车端计算与决策核心（VehicleAgent / VehicleDecisionCore）

- **英文与含义：** 前者是车端模块，后者是其中根据合法输入生成高层决策和求解请求的核心接口。
- **本项目用途：** 接收本车状态、有效观测、地图和消息，输出动作模式、原因、参考轨迹及控制求解请求。
- **易混点：** N02 已定义接口不等于已有完整避撞实现；核心输入不能含 CARLA 全局 World 句柄或隐藏目标真值。

### 2.9 控制执行器（ControlExecutor）

- **英文与含义：** 在实际执行周期接收可用控制结果、复核有效性并提交车辆控制的模块。
- **本项目用途：** 检查计划身份、期限、当前道路与车体约束；没有合格新结果时进入已验证的回退路径。
- **易混点：** 求解成功仅表示优化器返回结果，不等于结果在当前帧仍安全、有效；执行器不能无限等待计算线程。

### 2.10 主动安全与减损（Active Safety / Collision Mitigation）

- **英文与含义：** 主动安全是在事故发生前干预；减损是在物理上难以完全避免时降低碰撞速度或后果。
- **本项目用途：** 同时记录是否碰撞、碰撞速度、误干预和约束违反，区分完全避撞与部分改善。
- **易混点：** 一次仍发生碰撞的试验可能具有减损作用，但不能写成成功避撞；仿真改善也不是现实安全认证。

## 3 数据与样本

依据：[数据来源与验证方案](数据来源与验证方案.md)、[N03 数据审计说明](N03数据审计说明.md)。

### 3.1 V2X-Seq

- **英文与含义：** 公开的车路协同序列数据集，包含顺序感知 SPD 与轨迹预测 TFD 两部分。名称与用途见[官方仓库](https://github.com/AIR-THU/DAIR-V2X-Seq)。
- **本项目用途：** 分别提供真实交通轨迹和真实车路图像验证材料，与 CARLA 可交互实验互补。
- **易混点：** 同属一个系列不代表两部分可以直接逐帧配对，也不保证两个实验集合不存在原始场景重叠。

### 3.2 轨迹预测数据（TFD）

- **英文与含义：** Trajectory Forecasting Dataset，主要包含随时间变化的目标轨迹以及地图、交通信号等资料。
- **本项目用途：** N03 审计来源、字段、单位与质量，N04 建立样本，后续比较 CV、GRU、HiVT 与 RC-STGT。
- **易混点：** TFD 不是直接训练 YOLO 的图像加检测框数据；示例包只能检查流程，不能冒充正式数据规模或泛化结果。

### 3.3 顺序感知数据（SPD）

- **英文与含义：** Sequential Perception Dataset，提供连续车路感知资料；本项目按 RGB 图像路线准备标注、标定和时间信息。
- **本项目用途：** 验证真实图像中的检测、跟踪、定位、协同发现，以及从感知历史到预测输出的链条。
- **易混点：** 标注采用激光雷达坐标系，不等于在线算法读取点云；固定真实日志不能验证干预车辆后的避撞效果。

### 3.4 数据审计（Data Audit）

- **英文与含义：** 在建模前核对数据来源、版本、许可、文件、字段、单位、缺失和异常，并保留统计分母及原始定位。
- **本项目用途：** 区分原始行、有效行、文件内 ID、独立场景和可训练窗口，避免把坏时间戳或错误单位带入模型。
- **易混点：** 程序成功读取文件不等于数据通过审计；自行计算文件哈希也不证明来源官方、内容完整或使用许可成立。

### 3.5 场景、片段与运行（Scenario / Episode / Run）

- **英文与含义：** Scenario 描述布局和初始条件；episode 是一次连续演化片段；run 是某代码、配置、输入和种子下的一次执行。
- **本项目用途：** 同一基础场景可以分别运行无干预、仅车端和协同策略，并通过标识关联结果。
- **易混点：** 三个词的具体编号要看数据源定义；重复执行同一场景，不自动产生多个独立交通场景。

### 3.6 轨迹标识与命名空间（Track ID / Namespace）

- **英文与含义：** track_id 标记一条跟踪历史；命名空间将来源、传感器、会话和片段等身份一起纳入解释。
- **本项目用途：** 相机 A 的 track_7 与相机 B 的 track_7 先作为不同来源记录，再依据合法观测关联。
- **易混点：** 两侧相同数字不保证同一物理目标；跨视角直接相加 ID 数会重复计数，真值 ID 也不能作为在线关联捷径。

### 3.7 分组划分与数据泄漏（Group Split / Data Leakage）

- **英文与含义：** 先按原始记录、路口或 episode 划分集合，防止训练过程间接看到应当独立评价的信息。
- **本项目用途：** 同事件的两侧相机、重叠时间窗和控制分支继承同一组；归一化统计只从训练集拟合。
- **易混点：** CSV 行随机分开并不能保证独立；没有直接复制测试标签，也可能因相邻帧或相同场景泄漏得到虚高结果。

### 3.8 四类数据角色（Train / Validation / Calibration / Test）

- **英文与含义：** 训练集更新参数，模型验证集选择模型和超参数，风险校准集拟合风险映射与阈值，独立测试集评价冻结方案。
- **本项目用途：** 四种角色按原始场景隔离，官方协议与项目自建划分分别标注。
- **易混点：** 用于调参或选阈值的集合不能再称独立测试；拿不到官方测试标签时，项目留出集不能冒称官方测试结果。

### 3.9 滑动窗口与预测时域（Sliding Window / Prediction Horizon）

- **英文与含义：** 滑窗从连续序列提取历史输入与未来监督；时域是一次预测或规划覆盖的未来区间。
- **本项目用途：** 设计中的20个历史点若间隔0.1秒，首尾跨度是1.9秒；在线4秒预测与3秒规划承担不同职责。
- **易混点：** 这些是在线设计配置，TFD 实验仍按已审计协议；不同预测时域的误差不能直接横向比较，也不能补造缺失未来。

### 3.10 标签与真值（Label / Ground Truth）

- **英文与含义：** 标签是监督或评价所用参考；真值在本项目中通常指离线标注或仿真器可提供的真实状态。
- **本项目用途：** 未来位置用于训练监督，真实碰撞事件用于评价，离线可见标注用于检测评分。
- **易混点：** 真值也有来源和误差范围；在线输入不能读取隐藏目标或未来。标注轨迹预测结果与图像感知预测结果须分列。

### 3.11 实际碰撞标签（Actual Collision Label）

- **英文与含义：** 在指定时间范围和实际执行策略下，是否发生车体接触，并记录对象、时刻和碰撞速度等信息。
- **本项目用途：** 评价一次 CARLA 执行的真实仿真结果，区分无干预和不同干预策略。
- **易混点：** 固定轨迹接近不等于发生碰撞；原始真实数据未记录碰撞时，不能自行把近距离样本标成真实事故。

### 3.12 近冲突代理（Near-conflict Proxy）

- **英文与含义：** 用最小间距、到达冲突点的时间差等可测量量描述潜在危险；proxy 表示它替代的是难以直接观察的风险。
- **本项目用途：** 在没有实际碰撞标签的真实轨迹上，按预先定义的公式和阈值分析危险接近行为。
- **易混点：** 代理指标的阈值、时域和单位必须明确；它能支持近冲突分析，不能直接得出真实事故概率或实车避撞收益。

### 3.13 反事实标签与参考策略（Counterfactual Label / Reference Policy）

- **英文与含义：** 从相同干预前状态，分别执行“继续、刹车、转向”等分支并记录结果；参考策略说明风险基于主车何种基准行为，反事实分支还须声明外车响应或参考策略。
- **本项目用途：** 区分“制动后没撞”和“本来就不会撞”，比较候选动作的风险与减损效果。
- **易混点：** 仿真反事实是声明条件下的分支结果；它不能证明现实中同一事件的另一种结局，标签还要绑定时域和外车响应。

### 3.14 缺失值、掩码与归一化（Missing Value / Mask / Normalization）

- **英文与含义：** 缺失值表示未知，mask 指明某位置、速度、特征或监督是否有效；归一化将数值按确定规则变换到适合训练的尺度。
- **本项目用途：** 未知速度用 null 与无效标记表达；未来缺失不参与对应监督损失，缩放参数仅在训练集拟合。
- **易混点：** 真实零速度表示静止，与“没有速度信息”不同；观测、外推状态和特征有效性也不能只用一个含糊掩码混为一谈。

## 4 感知、定位与融合

本节对应“图像里发现目标，再得到可用的米制运动历史”。项目定义见[详细技术路线第6～7章及第21.2～21.4节](详细技术路线.md)、[工程架构](工程架构与文件结构设计.md)和[异构目标方案](算法成品与盲区鬼探头方案.md)。这里解释拟采用方法的职责，不表示相关节点已经实施。

### 4.1 目标检测与 YOLO 家族（YOLO）

- **英文与含义：** YOLO 来自 You Only Look Once，是目标检测模型家族。输入一张图像，输出车辆、行人等目标的类别、位置框和检测分数，解决“这一帧里有什么、在什么地方”的问题。
- **本项目用途：** 车端、路侧分别检测 RGB 图像，检测结果进入跟踪和地面定位。至少统一比较 YOLO26、YOLOv8、YOLO11；例如用相同标注评价行人召回、误检和推理耗时。
- **易混点：** 检测框还不是连续轨迹，也不是米制车体。版本号更大不代表本项目效果更好，官方性能数字和已有接入示例不能代替项目选型实验。

### 4.2 多目标跟踪（ByteTrack）

- **英文与含义：** ByteTrack 是多目标跟踪方法的专名，通过连续帧的框关联保持目标身份。其典型过程先匹配高分检测，再用低分检测恢复尚未匹配的已有轨迹，减少遮挡造成的断裂。
- **本项目用途：** 每个摄像头独立维护跟踪器，给同一车辆或行人的连续检测分配局部 track_id，形成像素位置历史。输入是逐帧检测，输出是带身份和生命周期的图像轨迹。
- **易混点：** 单摄像头编号不能直接作为车路共享身份；ByteTrack 也不自动完成像素到米的定位。低分框恢复已有轨迹，不等于任意低分孤立框都应新建可靠目标。

### 4.3 相机标定（Camera Calibration）

- **英文与含义：** Camera Calibration 指估计相机成像参数及其空间关系，使图像像素和真实几何建立可计算的联系。它通常涉及镜头参数、畸变、相机位姿以及用于求解的已知参考点。
- **本项目用途：** 为车端和路侧图像地面定位提供参数。例如已知路面标记的米制位置和图像坐标，可以估计映射，再用独立参考点检查定位误差。
- **易混点：** “求出参数”不等于标定可靠。共线点、集中在局部的对应点或错误坐标会造成退化；车载相机随车运动，必须使用该帧适用的位姿，不能照搬固定路侧相机的映射。

### 4.4 相机内参与外参（Intrinsics / Extrinsics）

- **英文与含义：** Intrinsics 是焦距、主点等相机内部成像参数；Extrinsics 是相机相对另一坐标系的旋转和平移。前者描述“怎样拍成图像”，后者描述“相机放在哪里、朝哪个方向”。
- **本项目用途：** 内参将相机空间点投影到像素，外参连接相机、车辆和地图坐标。车载相机需要组合相机安装位姿与当前车辆位姿，路侧相机通常使用固定外参。
- **易混点：** 外参方向必须明确，世界到相机和相机到世界互为逆变换。米、像素、弧度不能混算；展示用驾驶员相机与算法感知相机不重合时，也不能共享一套未经核实的参数。

### 4.5 单应性（Homography）

- **英文与含义：** Homography 是两个平面之间的投影映射，常用一个齐次矩阵表示。对符合平面假设的点，它能把图像坐标转换到另一平面，求解时可结合 RANSAC 排除异常对应点。
- **本项目用途：** 在经过验证的道路平面上，把目标接地点附近的像素转换为米制地面位置。输入是有效对应点和待转换像素，输出是位置及映射是否适用的检查结果。
- **易混点：** 单应性不能无条件恢复任意三维点。桥面、坡道、悬空框角点或错误接地点可能违反假设；残差小也不能替代远近距离、不同区域的独立定位验证。

### 4.6 地面投影与米制定位（Ground Projection）

- **英文与含义：** Ground Projection 指结合标定、地面假设和目标参考点，将图像里的目标位置转换为地面坐标。结果用米表示，才能与地图、车辆尺寸和运动模型共同计算。
- **本项目用途：** 将图像轨迹变成位置历史。例如车辆检测框底边附近的参考像素，经合法映射得到地图 x、y，并携带定位质量，供状态估计和预测使用。
- **易混点：** 检测框中心通常不等于地面接触点，框底也不保证在遮挡时可靠。像素检测准确不自动意味着米制定位准确；投影失败应显式无效，不能把离线真值位置补进在线输入。

### 4.7 世界坐标与局部坐标（World / Local Coordinates）

- **英文与含义：** World Coordinates 是地图等公共坐标；Local Coordinates 是相对某个原点和方向建立的坐标。两者通过旋转和平移互换，描述的是同一物理位置，不是两套不同事实。
- **本项目用途：** 预测输入可转换到预测起点的主车局部坐标，使“前方、左侧”等关系更统一；预测结果再转回公共地图坐标，供通信、风险计算和显示使用。
- **易混点：** 必须同时记录坐标系、锚点与方向。项目共享平面采用右手系，CARLA 数据需要明确转换；只改坐标名、不转换位置速度和航向，会制造错误的转向或碰撞结果。

### 4.8 几何中心与后轴参考点（Reference Point）

- **英文与含义：** Reference Point 是状态位置所对应的车上具体点。Geometric Center 是车体几何中心，Rear Axle 是后轴参考点；同一辆车的这两个点位置不同，不能直接互换。
- **本项目用途：** 自行车运动模型使用后轴参考点，OBB 碰撞几何以车体中心表示。转换时根据车身朝向和已知偏移计算中心位置，再进行车体接触或道路包含检查。
- **易混点：** 偏移应随航向旋转，不能永远沿世界 x 轴平移。轴距不等于后轴到车体中心的距离；不明确参考点，即使模型和几何各自计算正确，也会产生系统性的碰撞判断偏差。

### 4.9 跨来源关联（Cross-source Association）

- **英文与含义：** Cross-source Association 指判断不同传感器或处理来源中的目标是否对应同一物理对象。它需要可比较的时间、坐标、类别和位置，不是简单拼接两个编号列表。
- **本项目用途：** 将车端和路侧都看到的同一车辆关联为统一目标，同时保留只在路侧出现的目标。输入是合法可用的来源轨迹，输出包括匹配、未匹配、歧义及统一身份。
- **易混点：** 两个摄像头的 track_id 相同不代表同一目标，不同也不代表不同目标。不能用隐藏真值 ID 完成在线配对；有歧义时要保留不确定性，不能为了“融合成功”强行合并。

### 4.10 因果卡尔曼滤波（Kalman Filter）

- **英文与含义：** Kalman Filter 利用运动模型预测状态，再用新观测修正估计，同时维护不确定性。项目地面状态采用二维恒速度状态，包含位置和速度，更新只使用当时已可用的信息。
- **本项目用途：** 把抖动位置转换为较稳定的米制状态，并在短时漏检时向前外推。例如 x=0、速度 10 m/s，经过 0.1 s 的恒速预测位置为 1 m，同时传播协方差。
- **易混点：** 外推是模型估计，不是新观测，不能刷新 last_seen_time。ByteTrack 内部图像滤波与此处米制滤波不同；利用未来观测回头平滑的离线结果不能直接作为在线历史。

### 4.11 协方差（Covariance）

- **英文与含义：** Covariance 描述状态分量误差的大小和相关方向，矩阵对角元素是方差，非对角元素描述共同变化。它比“一个置信度分数”更适合表达二维位置误差的方向性。
- **本项目用途：** 卡尔曼滤波传播状态协方差，关联门控据此考虑位置不确定性；风险模块也可在来源明确、经过验证时，用位置协方差构造质量相关的保护裕量。
- **易混点：** 不知道误差不等于误差为零。协方差应有限、对称且半正定；检测分数不能直接充当位置方差，膨胀矩形后的保护性冲突也不能冒充真实车体已经碰撞。

### 4.12 马氏距离门控（Mahalanobis Gating）

- **英文与含义：** Mahalanobis Distance 用协方差对位置差异作尺度与方向归一化；Gating 是在正式匹配前剔除明显不合理的候选配对。它回答的不是单纯“相距几米”，而是“相对当前误差范围差多少”。
- **本项目用途：** 比较车端观测与路侧目标的预测位置，结合时间对齐和类别等条件形成合法关联候选，再交给最小代价分配处理。
- **易混点：** 门限依赖误差模型和维度，不能随意把一个距离当成真实概率。协方差严重低估会误拒绝，严重高估会误合并；门控失败时应保留未匹配目标，而非取消门控凑出匹配。

### 4.13 线性最小代价分配（Linear Sum Assignment）

- **英文与含义：** Linear Sum Assignment 是在“一项最多匹配一次”的约束下，选择总代价较小的一组配对。项目拟用 SciPy 的 linear_sum_assignment，其实现采用改进的 Jonker–Volgenant 算法。
- **本项目用途：** 将跨来源合法目标候选组成代价矩阵，并显式设置未匹配代价。例如对角代价低的两个对象，应一对一匹配，避免两个车端目标占用同一个路侧目标。
- **易混点：** 最优分配只说明给定代价下更优，不保证物理身份正确。必须先门控并允许未匹配；不能把任何矩阵都强制分配完，也不能笼统把当前所用实现都称为匈牙利算法。

### 4.14 交并比（IoU）

- **英文与含义：** Intersection over Union 是两个区域交集面积除以并集面积，常用于衡量检测框重叠程度。完全一致时为 1，没有重叠时为 0，数值本身不带米或像素单位。
- **本项目用途：** ByteTrack 可根据预测框与当前检测框的 IoU 形成图像关联代价；检测评测也会在明确类别、阈值和标注规则下判断框是否匹配。
- **易混点：** 图像 IoU 高不代表米制位置正确，远处的小框也可能因少量像素偏移产生明显变化。不同摄像头中的框不能直接求 IoU 来判断同一目标，IoU 也不是碰撞概率。

### 4.15 可见性与遮挡（Visibility / Occlusion）

- **英文与含义：** Visibility 描述目标是否能被某一观测来源看到，Occlusion 指视线被建筑、车辆等阻挡。几何上可见、传感器实际采到、检测器成功检出是相关但不同的三个条件。
- **本项目用途：** 区分“本车看不到但路侧看到”的有效协同场景，以及双方都无法观测的未知区域。评测分别记录首次几何可见、实际检测和消息可用时刻。
- **易混点：** 没有检测框可能是漏检，也可能是遮挡，不能直接推出道路安全。仿真可见性真值可用于离线评测，正式在线模块不能直接读取它来获知隐藏目标。

### 4.16 检测分数与观测质量（Detection Score / Observation Quality）

- **英文与含义：** Detection Score 是检测器对某个输出的评分；Observation Quality 泛指定位误差、来源可用性、时间年龄和关联可靠性等信息。它们衡量不同问题，不能压成一个未经定义的“可信度”。
- **本项目用途：** 检测分数用于跟踪和质量特征；位置误差与关联质量进入来源融合和保护裕量。例如框分数较高但地面投影退化时，仍应降低定位有效性或显式拒绝。
- **易混点：** 分数 0.9 不能直接解释为位置有 90% 准确，更不能解释为碰撞概率。低分目标也可能危险，不能仅因门控权重小就删除其潜在风险。

## 5 预测模型与训练

本节对应“把合法历史变成多种未来轨迹”。模型分工、输入与损失见[详细技术路线第8～9章及第21.6节](详细技术路线.md)，当前工作名称和研究边界见[研究方案](毕业设计研究方案.md)。官方接口依据包括 [PyTorch TransformerEncoderLayer](https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html)、[GRUCell](https://docs.pytorch.org/docs/stable/generated/torch.nn.GRUCell.html)和 [HiVT 作者实现](https://github.com/ZikangZhou/HiVT)；链接列为定义来源，不代表本次重新完成兼容性或可达性验证。

### 5.1 恒速度基线（CV）

- **英文与含义：** Constant Velocity 假设目标短时间维持当前速度和方向，以“当前位置 + 速度 × 时间差”产生预测。它不需要训练，作为最简单基线，可以先暴露坐标、时间和指标实现错误。
- **本项目用途：** 从最新有效米制状态外推未来。例如 state_time=0.2 s 时 x=2 m、v=10 m/s，在 anchor_time=0.3 s 的位置应为 3 m，再从该起点生成未来轨迹。
- **易混点：** 这里的 CV 不是 Computer Vision。已外推状态要从 state_time 继续推进，不能再次从原采集时刻推进；单条轨迹 K=1，复制六份不能称为学会多模态。

### 5.2 门控循环单元（GRU）

- **英文与含义：** Gated Recurrent Unit 是处理序列的神经网络单元，通过门控决定保留多少过去信息、加入多少当前信息。连续输入历史状态后，隐藏状态用于概括目标的运动变化。
- **本项目用途：** 作为学习型时序基线，按真实采样间隔和有效掩码处理历史，并输出多模式未来。项目普通 GRU 基线不加入图交互和地图编码，以便判断时序学习本身的作用。
- **易混点：** GRU 不会自动知道缺失值不是零速度，必须正确使用掩码。若增加地图或交互能力，应明确命名和比较范围，不能仍把它当作完全相同的普通基线。

### 5.3 Transformer 网络（Transformer）

- **英文与含义：** Transformer 是主要通过注意力机制建立输入之间联系的神经网络结构。它把历史点或地图等信息表示成特征单元，再学习哪些关系对当前预测更重要。
- **本项目用途：** 在历史窗口中编码加速、减速和转向趋势，并与交通参与者、道路上下文交互，输出未来运动。输入必须截至预测起点已经可用，网络不直接接管车辆执行器。
- **易混点：** 使用 Transformer 本身不等于算法创新，也不保证优于 GRU 或 CV。若全部输入已经是合法历史，历史窗口内部双向注意力可以合法；读取未来监督才会造成信息泄漏。

### 5.4 自注意力与交叉注意力（Self-attention / Cross-attention）

- **英文与含义：** Attention 通过查询、键和值计算信息权重。Self-attention 在同一组特征内部建立联系；Cross-attention 让一组特征从另一组信息中选择相关内容，例如目标从地图中提取道路信息。
- **本项目用途：** 时间注意力关注关键历史变化，目标交互注意力关注相关邻车，地图交叉注意力关注车道连接与冲突区。输入输出仍是特征，随后由解码器得到轨迹。
- **易混点：** 注意力权重不是碰撞概率，也不能单独证明模型的因果解释。有效性掩码必须在权重计算中生效；全部来源无效时需要明确缺失处理，不能对非法值继续归一化。

### 5.5 时空交互图（Spatio-temporal Interaction Graph）

- **英文与含义：** Spatio-temporal Graph 用节点和边表达交通参与者跨时间的运动及相互关系。“时”是历史演变，“空”是位置、道路连接、相对运动和潜在冲突关系，并非图像文件。
- **本项目用途：** 让横向来车、前车、行人等成为相关上下文。构图时既考虑邻近，也考虑道路或冲突关系，例如高速接近但当前距离较远的车辆仍可能重要。
- **易混点：** 只按距离截断可能删掉危险对象；连边也不能使用未来实际交会信息。加入图结构后是否有收益，必须用同数据和预算的比较、消融来判断，不能由模型名称推断。

### 5.6 可靠性感知车路协同时空图模型（RC-STGT）

- **英文与含义：** Reliability-aware Cooperative Spatio-Temporal Graph Transformer 是项目拟研究模型的工作名。它计划把来源可靠性融合、历史时间编码、目标图交互、地图交互与多模式解码串成统一预测网络。
- **本项目用途：** 输入车路合法历史及信息年龄、质量和有效掩码，输出各目标未来轨迹与权重。例如路侧观测变旧时，模型应结合年龄和其他来源评估如何融合，并保留不确定性。
- **易混点：** 这是本项目工作名称，不是已存在的论文方法或已经验证的创新。路侧来源不天然更准确；可靠性设计能否改善延迟、缺测表现，需要独立消融和实际实验支持。

### 5.7 层次化向量 Transformer（HiVT）

- **英文与含义：** Hierarchical Vector Transformer 是已有的多主体运动预测方法，使用向量化场景表示和层次化交互建模。项目把它作为强预测基线，以区别于简单运动模型和普通时序网络。
- **本项目用途：** 按作者实现及 V2X-Seq 对应适配建立独立基线，再转换到统一预测接口。比较前固定合法历史、对象、时域和评分协议，并记录原实现与适配之间的改动。
- **易混点：** RC-STGT 不应被称为“已经复现的 HiVT”。旧依赖能否支持当前 GPU 必须验证；使用作者公开指标或能导入代码，都不能作为本项目完成复现和训练的证据。

### 5.8 多模态轨迹预测（Multimodal Trajectory Prediction）

- **英文与含义：** Multimodal Trajectory Prediction 为同一目标保留多种可能未来，例如直行、转弯和减速，而非只输出一条平均路线。每种模式是一条完整未来轨迹，并有相应权重。
- **本项目用途：** 风险模块检查每种未来是否与本车候选动作冲突，再按声明方式汇总。这样可以保留虽不最常见但可能危险的横穿路线，而不是只看最可能模式。
- **易混点：** 这里的多模态不是“图像加文字”等多输入形式。不同目标同编号模式没有联合场景含义；不能把每个未来时刻随机选出的不同模式位置拼成一条合理轨迹。

### 5.9 模式分数与权重（Mode Logits / Mode Weights）

- **英文与含义：** Logits 是网络输出的未归一化分数；Softmax 可将有效模式分数变成非负、总和为 1 的权重。权重表示模型在所给模式之间的相对分配，不等于已经校准的客观频率。
- **本项目用途：** 预测输出 K 条轨迹和 K 个权重，风险模块保留它们的对应关系。例如两条模式权重为 0.7 和 0.3，能够分别报告哪条未来导致冲突。
- **易混点：** 权重和为 1 只是接口约束，不证明概率可信。模式分类校准不自动完成碰撞事件校准；无效模式应权重为零，不能让缺失轨迹参与正常风险平均。

### 5.10 有效掩码（Mask）

- **英文与含义：** Mask 是说明某个目标、时刻或特征能否使用的标记。项目区分 observed_mask、state_mask、feature_mask 和未来监督掩码，分别表示真实观测、有效状态、有效字段和有效标签。
- **本项目用途：** 目标短时漏检后可有外推状态，即 state_mask 有效而 observed_mask 无效；未知速度由 feature_mask 标明缺失，训练损失仅计算真实存在的未来标签。
- **易混点：** 未知速度不能填零后当作停车，缺失未来也不能用零坐标监督。去掉来源门控的消融仍要保留来源有效性掩码，否则同时改变信息可用性，会破坏公平比较。

### 5.11 来源门控与可靠性建模（Source Gating / Reliability Modeling）

- **英文与含义：** Source Gating 根据来源状态和质量，为车端、路侧等输入分配融合权重；可靠性建模显式考虑信息年龄、定位质量、关联可信程度和缺失情况。
- **本项目用途：** RC-STGT 拟将年龄、检测分数、位置不确定度和有效标记作为门控特征。路侧信息变旧时，学习怎样调整其作用，全部来源无效时进入明确缺失处理。
- **易混点：** 来源权重不是碰撞概率，权重较小也不能成为删除危险目标的理由。未知方差不能填为零；去掉门控的消融仍须保留合法性掩码，以免同时改变输入范围。

### 5.12 特征单元与嵌入（Token / Embedding）

- **英文与含义：** Token 是送入网络处理的信息单元；Embedding 是把原始数值或类别映射到特征向量的表示。项目中的 token 可以表示一个历史状态、目标、来源或地图折线，不要求是自然语言词语。
- **本项目用途：** 把位置速度、目标类别、来源和道路结构编码到可交互的向量空间，再送入注意力网络。例如行人与车辆使用类别信息，帮助模型区分不同运动规律。
- **易混点：** 向量维度大不代表信息更可靠。未知类别、缺失质量和无效来源需要显式表示；不能把未知定位误差嵌入为“误差零”，也不能借编码混入隐藏目标或未来真值。

### 5.13 平滑 L1 回归损失（Smooth L1 Loss）

- **英文与含义：** Smooth L1 是衡量预测数值与目标差异的回归损失，小误差区域较平滑，大误差区域不像平方损失那样快速放大。它用于训练位置等连续输出，具体尺度与权重须在配置中明确。
- **本项目用途：** 对匹配到的预测模式和真实未来位置计算回归误差，并按有效标签掩码汇总。输出是用于梯度更新的损失值，而非直接控制车辆的风险值。
- **易混点：** 训练损失下降不代表 ADE、危险召回或闭环碰撞率必然改善。坐标归一化后损失的数值尺度会改变，正式误差仍需还原为米并按统一评测口径报告。

### 5.14 交叉熵与胜出模式匹配（Cross-entropy / Winner Matching）

- **英文与含义：** Cross-entropy 是训练分类分数的损失。多模式轨迹训练可先找出与真实未来误差最小的模式作为匹配标签，再让网络提高该模式的分数，同时训练其轨迹回归。
- **本项目用途：** 在训练阶段利用未来标签确定 k*，为多模式解码器提供模式选择监督。回归和分类损失的权重必须明确，避免只让多条模式变成同一条路线。
- **易混点：** k* 依赖真实未来，只能用于训练或离线评分，在线控制不能读取。训练匹配标签不等于真实运动原因，分类权重也不能未经校准就解释为碰撞事件概率。

### 5.15 负对数似然（NLL）

- **英文与含义：** Negative Log-likelihood 用模型给真实观测分配的概率密度评价概率预测，值与所声明的分布形式、参数和单位有关。使用它必须先说明预测的是怎样的随机分布。
- **本项目用途：** 仅在启用明确的概率分布扩展时，为轨迹均值、尺度和混合权重提供相应训练或评测依据；基础离散轨迹加权方案不因输出权重就自动具有完整 NLL 定义。
- **易混点：** 单个时刻的位置方差不能自动定义整条未来的时间相关性。不能把未知协方差随意填入，也不能叠加未经说明的概率损失后，声称已经获得可靠的场景碰撞概率。

### 5.16 训练与推理（Training / Inference）

- **英文与含义：** Training 利用数据和损失更新模型参数；Inference 在给定模型参数后，根据合法输入计算预测。二者的计算路径、可用标签和性能统计目的不同，训练吞吐也不等于在线推理延迟。
- **本项目用途：** 训练入口读取声明的训练划分并保存权重；在线路侧推理只接收当时可用历史，输出带模型版本和绝对预测时间的轨迹。评估时还需固定相应模式和随机行为。
- **易混点：** 能运行一次前向不代表完成训练；小样本拟合不代表泛化有效。导入训练脚本不应触发训练，推理失败也不能自动用未来标签或演示数字补成成功结果。

### 5.17 梯度、反向传播与优化器（Gradient / Backpropagation / Optimizer）

- **英文与含义：** Gradient 表示损失对参数的变化方向；Backpropagation 计算这些梯度；Optimizer 根据梯度和自身状态更新参数。它们共同构成一次学习更新，但优化器名称本身不保证收敛。
- **本项目用途：** GPU 环境验收需运行小网络前向、反向及参数更新，检查损失和梯度有限、参数确实变化。正式训练还记录学习率、随机种子、预算和失败状态。
- **易混点：** 仅看到 GPU 名称或张量被创建不能证明可以训练。梯度为 NaN、参数不变或实际落在 CPU 都需要明确处理；测试集不能用于选择优化器或反复调整学习率。

### 5.18 检查点与恢复（Checkpoint / Resume）

- **英文与含义：** Checkpoint 是某次训练状态的保存，除模型参数外，恢复训练通常还需要优化器、步数和随机状态；Resume 是从该状态继续训练，而不是重新开始一个同名实验。
- **本项目用途：** 支持中断后恢复，并将模型与代码、配置、数据划分及哈希关联。验证时比较保存前后同一输入的评估输出，并检查恢复后的训练状态是否一致。
- **易混点：** 只有权重文件不代表能完整恢复训练。数据、配置或模型结构不兼容时应拒绝恢复；最好模型的选择依据必须来自预先声明的验证规则，不能看测试结果挑检查点。

## 6 时间与消息契约

本节按 [N02 数据契约字典](N02数据契约字典.md)、[通信方案](车路通信方案.md)及[工程设计](工程架构与文件结构设计.md)解释字段。示例只用于说明时间关系，不代表已测时延或已完成通信功能；实际结构以当前契约和后续节点验收为准。

### 6.1 观测采集时刻（observation_time）

- **英文与含义：** Observation time，传感器采集原始观测的时刻，例如相机拍摄某一帧的时间。
- **本项目用途：** 如果图像在 12.0 秒拍摄、12.08 秒完成检测，目标位置所依据的原始观测仍采集于 12.0 秒。它用于历史排序、信息年龄和因果检查。
- **易混点：** 检测完成、消息生成和接收时间都不能替换采集时间；把旧画面的处理完成时刻写成采集时间，会使系统误以为信息很新。

### 6.2 最近真实观测时刻（last_seen_time）

- **英文与含义：** Last-seen time，最近一次确实观测到目标的时间，记录“最后看见它是什么时候”。
- **本项目用途：** 目标在 12.0 秒后被遮挡，即使滤波器继续估计其 12.3 秒位置，最近真实观测仍是 12.0 秒，用于失联记忆及不确定性增长。
- **易混点：** 状态外推、旧消息重发、重复接收均不产生新观测，不能刷新 last_seen_time。无结果也不能自动解释成目标已离开。

### 6.3 来源端可用时刻（source_available_time）

- **英文与含义：** Source-available time，观测在来源端完成必要处理、能够被来源端使用的时刻。
- **本项目用途：** 车端相机 12.0 秒采集、检测跟踪在 12.08 秒完成，则这条处理结果最早在 12.08 秒可用于上传或本地计算。
- **易混点：** 它不是接收车辆的 usable_time。来源端处理完成后，还可能有上传、融合、预测、下发和接收处理，不能绕过这些环节直接提供给另一端。

### 6.4 状态所对应的时刻（state_time）

- **英文与含义：** State time，位置、速度等状态向量描述的时间，可晚于最近真实观测，表示已经进行因果外推。
- **本项目用途：** 目标在 0 秒位于 x=0、速度 10 m/s，外推至 0.2 秒得到 x=2，此时 state_time=0.2；再查询 0.3 秒，应得到 x=3。
- **易混点：** 再次从原采集时间外推会重复补偿，错误得到 x=5。state_time 更新不等于目标被重新看见，不能同时刷新 last_seen_time。

### 6.5 预测锚点（anchor_time）

- **英文与含义：** Anchor time，预测输出所依附的绝对时间起点；各未来轨迹点相对于该锚点定位。
- **本项目用途：** anchor=12.0 秒、采样间隔 0.1 秒时，首个未来点对应 12.1 秒。消息 12.2 秒收到后，查询 12.5 秒仍读取原来对应 12.5 秒的点。
- **易混点：** 不能把接收时刻改作新锚点，否则整条未来轨迹被向后平移。锚点也不是消息完成计算或开始执行控制的时刻。

### 6.6 预测输入截止（input_cutoff）

- **英文与含义：** Input cutoff，某次预测允许采用输入的时间边界，用于声明模型究竟知道了哪些信息。
- **本项目用途：** 截止为 12.0 秒时，12.05 秒才完成源端处理的观测不能参与该次预测，即使它的图像采集于 11.9 秒。N02 同时检查采集和源端可用时间。
- **易混点：** “采集于过去”不等于“当时已可用”。截止不晚于锚点，但二者不必相等；不能用截止后的未来帧补全历史再称实时预测。

### 6.7 计算完成、生成与发送（completed / generated / transmitted time）

- **英文与含义：** Completed time 表示计算结束；generated_time 表示消息生成；transmitted_time 表示发送时刻，分别描述不同步骤。
- **本项目用途：** 路侧在 12.10 秒完成预测、12.11 秒形成消息、12.12 秒发送，可据此拆分处理和发送前等待。实际字段组合由具体消息契约决定。
- **易混点：** 生成一条消息不意味着观测刚发生。同步仿真即使暂停等待推理，也不能将真实计算耗时自动计为零，更不能让尚未完成的结果提前发送。

### 6.8 接收到达与业务可用（arrival_time / usable_time）

- **英文与含义：** Arrival time 是接收侧记录的到达时刻；usable_time 是重组、解码、校验等完成后，业务逻辑可采用的时刻。
- **本项目用途：** arrival=1.0 秒、usable=1.2 秒时，1.1 秒的风险判断仍不得使用该消息。接收记录保留这两个时刻，便于复核信息使用是否合法。
- **易混点：** 两者由接收侧或调度器记录，发送侧不能伪造测得的接收元数据；对象构造成功、收到了字节，也不等于消息已能消费。

### 6.9 采用期限与预测终点（valid_until / future_end）

- **英文与含义：** Valid-until 是最后允许采用消息或结果的时刻；future_end 是预测轨迹覆盖的终点，分别限制新鲜度和未来覆盖。
- **本项目用途：** 预测到 16.0 秒，若预计 13.1 秒开始执行 3 秒计划，就缺少到 16.1 秒的覆盖，即便采用期限尚未到也要降级处理。
- **易混点：** 两个字段不能互换，也没有对所有对象统一规定的先后关系。全局预测终点不能替代各目标有效掩码，个别目标可能更早失去有效未来。

### 6.10 执行起点与任务截止（plan_start_time / deadline）

- **英文与含义：** Plan-start time 是预计执行计划的起点；deadline 是计算或任务必须交付结果的截止时间，均须说明时钟域。
- **本项目用途：** 计划 12.25 秒开始执行，可要求求解任务在 12.15 秒前结束，为安全复核和提交控制预留时间。风险评估按执行起点对齐预测。
- **易混点：** deadline 允许早于 plan_start_time，不能写成固定相反关系。请求提交时间也不是执行时间；结果按时算出后仍须复核有效期与当前约束。

### 6.11 时钟域、仿真时钟与墙钟（clock_domain / simulation time / wall-clock）

- **英文与含义：** Clock domain 表示共同时间基准；simulation time 是仿真世界时间，wall-clock 是机器实际经过的时间。
- **本项目用途：** CARLA 由唯一调度器推进仿真时间，在线耗时另用实际计时记录。仿真停下等待计算一秒，世界未前进不表示计算只耗时零秒。
- **易混点：** 同为秒的数值也可能属于不同域，不能直接相减。跨设备单向时延须考虑同步偏差；同一实测耗时与注入延迟不能重复累计。

### 6.12 信息年龄（Information age）

- **英文与含义：** 信息年龄表示从真实采集到当前采用之间已经过去多久，用来描述信息的新鲜程度。
- **本项目用途：** 12.0 秒的观测在 12.3 秒用于决策，年龄为 0.3 秒。车路融合后逐来源、逐目标保留年龄，可靠性模型据此处理旧输入。
- **易混点：** 网络时延只是年龄的一部分，还可能包括感知、排队、推理和等待。消息刚生成不说明其输入很新，4 秒预测时域也不能消除锚点之前的陈旧信息。

### 6.13 消息可用性检查（require_available）

- **英文与含义：** require_available 是当前 N02 接收对象提供的可用性检查入口，判断声明的消息在给定决策时刻是否满足相应时间约束。
- **本项目用途：** 消费方传入当前 Timestamp，检查采集、处理、状态、到达、可用和采用期限。后续调度仍需负责真实交付、重复拒绝及预测覆盖等其他条件。
- **易混点：** 构造 ReceivedMessage 成功不代表以后任意时刻都可消费；检查函数不能自动替代信道模拟或安全复核。时间字段要完整传入，不能只检查 arrival_time。

### 6.14 在线因果性与未来信息泄漏（Online Causality / Future Leakage）

- **英文与含义：** 在线因果性要求决策只依赖当时已合法可用的信息；未来信息泄漏是借助未来帧、未来标签或尚未送达的内容改善当前输出。
- **本项目用途：** 即使标注和仿真器已保存整段轨迹，当前模型也只读取输入截止之前可用的历史；修改未来标签后，当前输入哈希应保持一致。
- **易混点：** 已经采集却仍在处理或传输的信息也可能不能用。历史窗口内部双向注意力可以合法，关键是所有输入是否来自合法历史；分组泄漏则是另一种数据集合隔离问题。

## 7 通信信道与带宽

本节以 [通信方案](车路通信方案.md)及[节点计划](项目节点实施与验收计划.md)为项目依据。软件信道、进程通信、UDP 原型与真实 C-V2X 设备验证属于不同层级；以下容量数值是解析示例，不是本项目实测网络性能。

### 7.1 车路双向通信（V2X / V2I / I2V）

- **英文与含义：** V2X 为 Vehicle-to-Everything；V2I 为车到基础设施，I2V 为基础设施到车，分别表示上传和下发方向。
- **本项目用途：** 车端上传自身状态及可观测目标，路侧融合后下发带时间和质量信息的目标状态与预测轨迹，车端做最终决策。两个方向分别模拟延迟、丢包和容量。
- **易混点：** 路侧不能绕过上传链路直接读取车端缓存。10 Hz 上传与预测更新是起步设计，不是 V2X 标准强制频率，20 Hz 车端执行也不必等待每次下发。

### 7.2 路侧与车载通信单元（RSU / OBU）

- **英文与含义：** RSU 为 Roadside Unit，路侧单元；OBU 为 On-Board Unit，车载单元，在此主要承担车路通信收发。
- **本项目用途：** 真实部署设想由路侧摄像头、边缘计算、RSU、OBU 和车载计算组成链路；摄像头负责采集，算法处理与最终车辆控制另有职责。
- **易混点：** RSU 不自动等于摄像头或完整边缘服务器，OBU 也不自动等于避撞控制器。当前软件原型不代表已经拥有、部署或测试这些真实设备。

### 7.3 直接接口与移动网络接口（C-V2X / PC5 / Uu）

- **英文与含义：** C-V2X 为 Cellular Vehicle-to-Everything；PC5 表示直接通信接口，Uu 表示通过蜂窝移动网络连接的接口。
- **本项目用途：** 真实架构设想可用 PC5 进行车路直接通信，或经 Uu 连接应用服务器；毕设先在软件中研究时延与失联对预测、避撞的影响。
- **易混点：** 软件中设定某个丢包率，不等于复现 PC5 的射频、拥塞和资源调度。不能将 PC5 简单解释成“必须先连运营商网络”，也不能把接口名称当成设备验收。

### 7.4 软件信道与事件调度（SimChannel / Event scheduling）

- **英文与含义：** 软件信道是按仿真时间安排消息交付的机制；事件调度按到达时刻及稳定序号处理消息。
- **本项目用途：** N08 拟用最小堆分别调度 V2I、I2V。12 秒发送、固定延迟 0.2 秒的夹具在 12.19 秒不交付，12.20 秒交付一次。
- **易混点：** 同刻消息须稳定排序，不能直接比较消息对象。上述夹具显式不计容量服务；加入带宽和排队后到达时间须相应改变，不能混用两套断言。

### 7.5 时延与抖动（Latency / Jitter）

- **英文与含义：** Latency 是一次处理或传输花费的时间；jitter 是这些时延随消息变化的波动，二者应说明起止点。
- **本项目用途：** 分别记录感知、上传、融合、预测、下发、接收处理和执行耗时。可先用固定延迟联调，再注入有界波动观察风险变化。
- **易混点：** 网络传播时延不等于端到端决策时延，平均值也会掩盖少量超期。应保留分布、p50/p95、最大值和超期率，并说明丢弃包是否进入统计。

### 7.6 丢包与突发断联（Packet loss / Burst outage）

- **英文与含义：** 丢包指部分消息或分片无法交付；突发断联指一段连续时间不可通信，与逐包独立随机丢失不同。
- **本项目用途：** 可用独立 Bernoulli 丢包检查基础行为，再用预生成断联区间测试已知危险目标失联后的风险记忆与谨慎策略。
- **易混点：** 丢包不能刷新最近观测时间，也不能让危险目标立刻消失。各策略应共享按消息身份绑定的扰动，不能因抽样次数不同而获得不同通信条件。

### 7.7 乱序、重复与会话身份（Out-of-order / Duplicate / Session）

- **英文与含义：** 乱序是晚发先到；重复是同一内容再次送达；session_id 区分设备或进程重启后的会话，sequence 标记会话内顺序。
- **本项目用途：** 接收端结合来源、会话、序号及场景身份，拒绝旧包覆盖新状态，防止上一轮仿真的预测进入当前决策。
- **易混点：** 不能只凭一个 track_id 或 sequence 判断全局唯一性。重发旧观测不使其变新，跨摄像头相同数字 ID 也不代表同一物理目标。

### 7.8 应用层消息寿命（TTL）

- **英文与含义：** TTL 为 Time to Live，此处指应用消息允许被采用的寿命或有效期约束，需明确起算点和换算方式。
- **本项目用途：** 按消息 valid_until 拒绝过期内容；即使收到旧预测，也只能记入审计，不能驱动当前控制。
- **易混点：** 这里的寿命约束不能与 IP 包按跳数递减的 TTL 混用。未过期只通过一项检查，还须满足来源、可用时刻、观测年龄和未来覆盖等条件。

### 7.9 带宽与吞吐（Bandwidth / Throughput）

- **英文与含义：** 带宽在此表示信道可提供的数据率；吞吐是实际传送的数据率。bit/s 与 byte/s 相差八倍。
- **本项目用途：** 20 目标、6 模式、40 点、二维 float32，仅坐标为 38,400 字节；10 Hz 为 3.072 Mbit/s，可用来估计链路压力。
- **易混点：** 该算式不含封装、质量字段、签名和多车收发开销，不是实测结果。采用二进制序列化也不会自动消除浮点数组的数据量。

### 7.10 服务时间与排队（Service time / Queueing delay）

- **英文与含义：** 服务时间是消息占用发送能力的时间；排队延迟是等待前序消息完成产生的时间，二者与传播延迟分别记录。
- **本项目用途：** L 字节、容量 C bit/s 的服务时间为 8L/C。38,400 字节在 1 Mbit/s 下需 0.3072 秒，10 Hz 输入将积压或触发淘汰策略。
- **易混点：** 带宽不足时不能仍让所有消息零排队交付；两个方向共享物理资源时，还须共享调度。独立双向容量只是首版软件模型的简化假设。

### 7.11 数据报、可靠流与进程通信（UDP / TCP / IPC）

- **英文与含义：** UDP 是 User Datagram Protocol；TCP 是 Transmission Control Protocol；IPC 是 Inter-Process Communication，指进程间通信。
- **本项目用途：** 先用同机进程通信联调，再在获准扩展中验证 UDP 收发；低频配置和日志可走独立可靠通道，实时控制仍需自己的截止与有效性规则。
- **易混点：** UDP 不保证交付和顺序，TCP 的可靠字节流也不保证及时到达。同机 IPC 成功不代表跨机器网络或真实 C-V2X 设备已经验证。

### 7.12 最大传输单元与重组（MTU / Fragmentation / Reassembly）

- **英文与含义：** MTU 为 Maximum Transmission Unit；fragmentation 与 reassembly 分别表示分片和重组，须区分网络层与应用层处理。
- **本项目用途：** 大预测包可按目标、模式或时间块分片，携带身份、片号和总片数，并设置重组截止和内存上限；完整后才进入风险计算。
- **易混点：** 不能假设任意 38 KB 消息都适合直接发一个 UDP 数据报，也不能把丢片目标静默删除。具体载荷上限按路径与封装开销核验，示例值不是通用保证。

## 8 风险与碰撞几何

本节对应“在明确时间范围和参考策略下，判断候选动作会不会与目标冲突”。定义见[详细技术路线第10章及第21.7～21.8节](详细技术路线.md)、[研究方案](毕业设计研究方案.md)和[数据契约](N02数据契约字典.md)。校准方法来源包括[温度缩放原论文](https://proceedings.mlr.press/v70/guo17a.html)与[单调回归官方接口](https://scikit-learn.org/stable/modules/generated/sklearn.isotonic.IsotonicRegression.html)；算法来源与本项目实际校准结果分别记录。

### 8.1 碰撞事件与近冲突代理（Collision Event / Near-conflict Proxy）

- **英文与含义：** Collision Event 是声明条件下的车体接触事件；Near-conflict Proxy 是最小间距等用于描述危险接近的替代指标。二者都必须说明时间范围和参考运动或控制策略。
- **本项目用途：** 分别记录实际仿真碰撞、预测几何冲突、保护裕量冲突和数据中的近冲突代理。例如最小车体间距较小可作为代理，却不能直接标成已经发生真实碰撞。
- **易混点：** AEB 成功后没有碰撞，不代表原告警必然是误报。反事实无干预分支和实际干预分支要明确区分；固定日志不能证明另一种控制实际会怎样改变真实道路结果。

### 8.2 有方向包围框（OBB）

- **英文与含义：** Oriented Bounding Box 是带朝向的矩形或盒体。本项目车辆平面风险使用米制旋转矩形，包含中心位置、航向、长度和宽度，比仅用中心点更能表达车体占用空间。
- **本项目用途：** 把本车候选轨迹和周围目标预测转换为每个时刻的车体区域。例如两辆 4×2 m 车辆沿同一方向排列，纵向中心距离 4.0 m 时恰好接触，4.1 m 时分离。
- **易混点：** 此处地面车体 OBB 不等于图像检测 OBB。长度、宽度和中心参考点必须一致；尺寸未知需要标记及声明先验，不能用零尺寸让目标在几何检查中消失。

### 8.3 分离轴定理（SAT）

- **英文与含义：** Separating Axis Theorem 判断凸形状是否相交：只要存在一条轴，使两个形状的投影区间分离，它们就不相交。对旋转矩形，需要检查车体边法向等适用轴。
- **本项目用途：** 输入两辆车的中心、半尺寸和朝向，输出相交或分离，用于逐模式、逐候选动作的碰撞事件计算。边界相切按项目声明的接触口径处理。
- **易混点：** 只检查世界 x、y 投影会漏掉旋转车体的分离轴。数值 epsilon 和安全裕量应分别说明，SAT 的单时刻相交结果也不能代替完整运动区间的碰撞检查。

### 8.4 按类别设置碰撞形状（Geometry by Participant Type）

- **英文与含义：** Geometry by Participant Type 指根据参与者类型选择合适的占用几何。汽车、行人和骑行者形状与运动特点不同，不能只修改分类名称而继续使用完全相同的车体模型。
- **本项目用途：** 车辆使用 OBB，行人与本车可用圆和旋转矩形的最近点关系检查，骑行者使用经过声明与验证的 OBB 或其他近似；尺寸和保护裕量分别配置。
- **易混点：** 将行人套成汽车大小会改变误警和可行性，将其当点又会漏掉接触。人和自行车检测可能属于同一骑行者，必须避免重复计为两个独立物理目标。

### 8.5 连续区间碰撞检查（Interval Collision Checking）

- **英文与含义：** Interval Collision Checking 关注两个采样时刻之间是否发生接触，而不只检查离散点。目标速度较高时，前后采样点都不重叠，运动过程中仍可能穿过本车。
- **本项目用途：** 根据运动速度、尺寸进行时间细分，或采用声明的扫掠近似，并保存细分规则和误差范围。例如目标在两帧之间横穿冲突区，区间检查应识别出这次潜在接触。
- **易混点：** 把采样加密称为“完全连续且绝对安全”不准确。必须说明插值、运动假设和误差，基础预测间隔 0.1 s 不能自动保证捕捉所有高速碰撞。

### 8.6 安全裕量与占用膨胀（Safety Margin / Occupancy Inflation）

- **英文与含义：** Safety Margin 是在车体或道路边界上增加的保护余量，用来容纳定位、预测及执行误差。Occupancy Inflation 是据此扩大占用区域的几何操作，不是改变目标真实尺寸。
- **本项目用途：** 比较固定裕量和质量相关裕量，例如有可靠位置协方差时适当扩大远期保护区域，并记录实际使用的误差来源、计算规则和适用范围。
- **易混点：** 膨胀区域重叠表示保护性冲突，不等于实际碰撞。裕量不是越大越好，过大会导致无谓干预；未知误差不能编造为精确协方差，也不能默认误差为零。

### 8.7 有效风险时域与覆盖完整性（Effective Horizon / Coverage）

- **英文与含义：** Effective Horizon 是所有相关预测和本车计划共同有效的未来时间范围；Coverage 描述是否完整覆盖所需规划时域。消息未过期与预测仍够长是两个独立条件。
- **本项目用途：** 所有候选动作在同一有效窗口比较，并记录 coverage_complete。例如要求执行起点后 3 s，而某危险目标仅剩 2.8 s 预测，不能只因前 2.8 s 无冲突就批准正常通过。
- **易混点：** 不能删除缺预测目标来获得“完整覆盖”，也不能把旧预测的起点平移到接收时刻。校准阈值绑定时域，原来 3 s 的事件阈值不能未经验证套在缩短的窗口上。

### 8.8 模式加权事件评分（Mode-weighted Event Score）

- **英文与含义：** Mode-weighted Event Score 先判断每种预测模式在指定时域内是否与某个本车动作冲突，再把冲突指示按模式权重加总。它是模型给定离散未来下的原始风险评分。
- **本项目用途：** 两个模式权重为 0.7 和 0.3，只有首模式冲突，则该目标对该动作的原始评分为 0.7。每个模式在窗口内发生一次或多次接触都只计一次事件。
- **易混点：** 数值处于 0～1 不代表是真实碰撞概率；需要适用的事件校准和证据。不能把多个冲突帧的分数累加成概率，评分还必须绑定候选动作、目标类别和时间范围。

### 8.9 多目标边际与场景总体风险（Marginal / Joint Risk）

- **英文与含义：** Marginal Risk 是各目标分别产生的事件风险；Joint Risk 描述多个目标共同作用下的场景事件。单目标预测通常没有定义各目标未来之间的联合相关结构。
- **本项目用途：** 首版分别报告最大边际评分和截断边际和。例如两个目标评分为 0.7、0.4，最大值为 0.7，截断和为 1，二者具有不同的工程含义。
- **易混点：** 它们都不能直接称为精确场景碰撞概率或真实安全上界。同编号模式不能跨目标直接拼成联合未来，使用独立事件公式也需要明确、验证过的独立性假设。

### 8.10 未知区域与风险记忆（Unknown Region / Risk Memory）

- **英文与含义：** Unknown Region 是当前合法观测无法覆盖的空间；Risk Memory 是对先前已经观测到的危险目标保留有限历史与不确定性的机制。未知空间与已知目标暂时失联属于不同情况。
- **本项目用途：** 双方都看不到的遮挡区域触发谨慎视野策略；已观测危险车辆短时失联时，保留来源时间并扩大运动不确定性，避免漏检一帧就立刻清空风险。
- **易混点：** 未知区域不能虚构一个确定隐藏目标，也不能被当作安全空地。外推和重发都不是新观测；风险记忆需要有限规则，不能无限保留一个永远不会失效的“幽灵目标”。

### 8.11 温度缩放与模式校准（Temperature Scaling）

- **英文与含义：** Temperature Scaling 用一个正温度调整分类 logits 的尺度，再归一化为权重，目标是改善分类权重与实际结果频率的对应关系，通常不改变 logits 的排序。
- **本项目用途：** 冻结轨迹网络后，在专用风险校准集上拟合模式温度，并保存参数和适用模型。例如降低过度集中的模式权重，评价是否更符合轨迹匹配结果。
- **易混点：** 模式标签来自轨迹匹配，不是碰撞事件标签，所以模式校准不能代替事件校准。不能在测试集拟合温度，也不能让模型验证集同时承担未经隔离的校准拟合角色。

### 8.12 单调事件校准（Isotonic Regression）

- **英文与含义：** Isotonic Regression 是在保持单调关系的约束下拟合数值映射的方法。事件校准可用它把原始评分映射成指定事件的频率估计，具体适用性取决于样本覆盖和标签定义。
- **本项目用途：** 在独立校准资料中，固定模型、参考动作、类别和时域，再拟合评分到事件结果的映射；阈值选择另遵守预登记划分或分组交叉验证规则。
- **易混点：** 只有一种标签、评分不变或样本不足时，应报告无法支持校准。在保持行驶动作上拟合的映射，不能直接套给所有制动转向动作；危险压力集合的频率也不等于自然交通概率。

## 9 规划、控制与执行

本节对应“先判断动作可行，再执行并监控”。设计见[详细技术路线第11～12章及第21.9节](详细技术路线.md)、[车端算法接口](算法成品与盲区鬼探头方案.md)与[工程调度](工程架构与文件结构设计.md)。方法和接口来源包括 [MPC 官方说明](https://www.mathworks.com/help/mpc/gs/what-is-mpc.html)、[CasADi 文档](https://web.casadi.org/docs/)及 [IPOPT 选项](https://coin-or.github.io/Ipopt/OPTIONS.html)。下列数值例子只用于理解定义，正式限制以获准节点实测冻结结果为准。

### 9.1 自动紧急制动（AEB）

- **英文与含义：** Automatic Emergency Braking 指在满足危险触发条件时主动施加制动。它可能避免碰撞，也可能在物理距离不足时只降低碰撞速度，必须根据具体场景评价。
- **本项目用途：** 车端根据当前合法信息，比较制动候选风险并生成制动请求，再经执行器映射施加到 CARLA。基线包含 TTC 触发和预测风险触发，以区分风险计算方法的影响。
- **易混点：** AEB 不是只要触发就能停住，停车距离取决于速度、延迟、制动力和 jerk。路侧发送风险提示不等于拥有最终制动权限，原始 brake 数值也不等于指定的物理减速度。

### 9.2 自动紧急转向（AES）

- **英文与含义：** Automatic Emergency Steering 指通过紧急转向调整运动轨迹以规避危险，也可与制动组合。它要求存在可行侧向空间，并满足车辆和道路约束。
- **本项目用途：** 在纯制动不足或转向更合适的条件下，生成左右侧向候选，检查车体、侧前后车辆、行人、道路边界和附着能力，再交给控制器跟踪。
- **易混点：** “前方危险”不能直接推出“向旁边转就安全”，看不清的侧向通道不能当成空闲。AES 无可行候选时应明确失败或选择减损策略，不能强行展示一次成功转向。

### 9.3 预计碰撞时间（TTC）

- **英文与含义：** Time to Collision 是在声明的运动假设下，预计距离首次车体接触还有多久。它依赖几何、相对运动和预测时域，不能脱离假设笼统解释为真实剩余反应时间。
- **本项目用途：** TTC-AEB 使用当时可用状态作恒速度车体外推，复用几何检查寻找时域内首次潜在接触。它与预测风险 AEB 共用执行条件，便于比较触发机制。
- **易混点：** TTC 是时间，不是概率；简单距离除相对速度只适合相应直线条件，不能随意用于交叉轨迹。没有预测接触应返回明确无事件状态，不在 JSON 写入 Infinity 冒充合法数值。

### 9.4 道路相对坐标（Frenet Coordinates）

- **英文与含义：** Frenet Coordinates 相对一条参考道路曲线描述位置，s 表示沿参考线的进度，d 表示横向偏移。它使沿路前进和侧向避让可以分开表达，再转换回地图坐标。
- **本项目用途：** 生成本车保持、向左或向右避让的候选。例如先决定沿道路的速度过程，再构造有限时间内的横向偏移，组合得到路径及其曲率。
- **易混点：** 每条路不都存在固定宽度的相邻车道，侧移范围必须来自实际可行驶区域。Frenet 变换有适用条件和奇异情况；停车后不能仍让车辆发生无物理依据的横向平移。

### 9.5 五次多项式侧向轨迹（Quintic Polynomial）

- **英文与含义：** Quintic Polynomial 是最高五次的多项式，可通过起终点的位置、速度和加速度六个边界条件求系数，生成平滑的侧向变化过程，并计算速度、加速度和 jerk。
- **本项目用途：** 输入初始横向状态、允许终点偏移和时长，输出 d(t) 及其导数，再与纵向运动组合成地图轨迹，检查曲率、车体道路包含和目标风险。
- **易混点：** 曲线平滑不代表车辆一定能执行，也不代表道路上没有障碍。纵向或横向分量各自满足某项限制，不自动意味着组合后的真实速度、加速度和 jerk 都满足约束。

### 9.6 候选动作与风险筛选（Candidate Actions）

- **英文与含义：** Candidate Actions 是从当前本车状态生成的一组可能行动，如保持、不同强度制动、左右避让及制动转向组合。每个动作包含未来轨迹、时域和所需控制，而不只是一个文字标签。
- **本项目用途：** 先剔除道路和动力学不可行候选，再对剩余动作使用相同有效窗口计算风险，保留采用和拒绝原因。风险相近时可进一步比较速度损失、控制变化和道路偏差。
- **易混点：** 预测网络给出的本车未来不是可直接执行的命令。候选库也不能假定总有安全动作；无安全候选必须记录减损或失败，不能只返回排序第一项并宣称安全。

### 9.7 硬约束与软代价（Hard Constraints / Soft Costs）

- **英文与含义：** Hard Constraints 是候选或求解结果必须满足的限制；Soft Costs 是满足基本条件后用于偏好比较的代价。例如道路边界可作为硬约束，偏离参考线可进入软代价。
- **本项目用途：** 对车体道路包含、转角和制动能力等设置明确检查，之后才比较路径跟踪误差、舒适性和通行损失。每个不满足条件的动作都记录具体原因。
- **易混点：** 在代价中给危险项一个大权重，不等于严格保证不会违反它。软约束的松弛也需要声明含义；不能为得到“求解成功”而静默放宽物理或道路限制。

### 9.8 六状态自行车模型（Six-state Bicycle Model）

- **英文与含义：** Bicycle Model 将同轴车轮简化为前后两个等效轮。项目六状态为后轴位置 x、y、航向 ψ、速度 v、加速度 a、转角 δ，控制量为 jerk j 和转角变化率 ω。
- **本项目用途：** 根据当前状态和控制预测本车运动，使 MPC 能直接约束加速度变化、转向速率等。简化四状态模型用于理解或基础比较，正式执行还要结合车辆标定。
- **易混点：** “自行车”是汽车运动学近似名称，不表示骑行者预测模型。它依赖简化假设，不能自动覆盖高速侧滑等工况；轴距、参考点和转角单位都必须与实际车辆对应。

### 9.9 四阶龙格—库塔积分（RK4）

- **英文与含义：** Classical Fourth-order Runge–Kutta Method 是把连续微分方程推进一个离散时间步的数值方法，通过步内多个导数估计得到下一状态，通常比单次欧拉推进更准确。
- **本项目用途：** 在给定步内控制及本车运动模型下，计算六状态下一时刻的预测，用于 MPC 的状态约束和参考轨迹检查。输入是当前状态、控制、步长和模型参数。
- **易混点：** RK4 提高的是所选模型的积分近似精度，不会修复错误模型或参数，也不会提供真实未来。它与 CARLA 物理引擎的实际运动仍可能不同，需要执行标定与回归验证。

### 9.10 模型预测控制（MPC）

- **英文与含义：** Model Predictive Control 根据本车模型，在有限未来时域内优化控制序列，只执行当前一步，再根据新状态滚动求解。它可以同时处理轨迹偏差、控制变化和明确约束。
- **本项目用途：** 跟踪上游已经筛选的本车参考路径与速度，并输出可执行控制计划。优化后的运动仍需检查道路、车体、时间覆盖和风险，不能假设它与原候选完全相同。
- **易混点：** 项目首版 MPC 主要是跟踪控制器，不等于全部风险决策。求解器返回成功也不等于结果安全或按时可用；控制循环不能无限等待一个已经超时的解。

### 9.11 符号建模与自动求导工具（CasADi）

- **英文与含义：** CasADi 是用于表达数值优化和微分计算的工具，能以符号形式建立状态、控制、目标函数与约束，并向优化求解器提供计算及导数信息。名称保留专名，不强行展开缩写。
- **本项目用途：** 用其 Opti 等接口描述六状态 MPC 的变量、参数、RK4 运动关系和道路约束，再调用指定求解器，保存求解状态及独立残差检查结果。
- **易混点：** CasADi 本身不是车辆模型、风险判断方法或实时安全保证。脚本能够构建优化问题不代表已完成控制；求解时限、异常处理和执行器映射仍需分别实现与实测。

### 9.12 内点优化求解器（IPOPT）

- **英文与含义：** Interior Point OPTimizer 是求解大规模连续非线性优化问题的软件。它依据给定目标、约束和导数迭代寻找解，常与 CasADi 组合使用，但不能保证任何非凸问题都找到全局最优。
- **本项目用途：** 计算 MPC 的控制序列，配置容差、迭代和求解预算，并记录成功、无解、数值失败或超时等状态。执行侧只采用期限内且经过复核的结果。
- **易混点：** 内部 CPU 时间选项不等于外层严格墙钟截止，具体行为还受构建和环境影响。不能因为选项写了 40 ms，就声称目标硬件端到端一定满足相应实时预算。

### 9.13 加加速度（Jerk）

- **英文与含义：** Jerk 是加速度对时间的变化率，单位 m/s³。例如加速度从 0 在 1 s 内匀速变化到 -2 m/s²，该段 jerk 为 -2 m/s³，描述的是刹车力度变化有多快。
- **本项目用途：** 生成受限 S 曲线制动剖面，并在六状态模型中直接以 j 作为控制量，让减速建立和释放过程更可控，同时记录舒适性及控制变化。
- **易混点：** jerk 不是加速度，减速度上限和 jerk 上限需要分别规定。具有有限 jerk 不保证停车距离一定足够；停止附近还需避免速度积分成负值，并处理加速度释放和停车保持等边界。

### 9.14 比例积分微分控制与前馈（PID / Feedforward）

- **英文与含义：** Proportional–Integral–Derivative 根据当前误差、累积误差和变化趋势修正控制；Feedforward 根据已知模型或标定直接给出基础控制量。二者可以结合，补偿模型与实际执行之间的偏差。
- **本项目用途：** 把期望速度、加速度或转角转换为 CARLA 可接受的控制，利用实测标定提供基础映射，再由反馈修正跟踪误差。输出仍要经过限幅和失效检查。
- **易混点：** PID 不是碰撞风险评估器。积分累积、控制饱和及低速工况需要处理，不能把“能跟住速度”当成已完成制动转向组合或全场景避撞验收。

### 9.15 执行器映射与标定（Actuator Mapping / Calibration）

- **英文与含义：** Actuator Mapping 把物理请求转换为油门、制动和归一化转向；Calibration 通过实际运行测量这些输入对应的响应、延迟和有效范围，使映射具有车辆和工况依据。
- **本项目用途：** 测试直线加减速、制动停车、正负转向及组合请求，记录请求与实际速度、加速度和航向。例如期望减速度不能仅靠把 brake 设成某个数就认定已经实现。
- **易混点：** 相同控制数值在不同车型、速度或附着条件下未必相同。油门与制动需互斥，转向需考虑限幅和速率；超出标定范围不能外推后宣称物理保证。

### 9.16 失效回退与降级（Fallback / Degraded Mode）

- **英文与含义：** Fallback 是在消息失效、模型异常、求解失败等条件下采用的受控处理；Degraded Mode 是能力受限时的运行状态。它们需要明确触发、动作、持续时间与恢复条件。
- **本项目用途：** 通信中断时保留合法本地估计和 AEB，MPC 无有效解时采用经过标定和复核的制动转向回退，并记录原因。已知失联目标和从未看到的未知区域分别处理。
- **易混点：** 回退不等于绝对安全，残余风险仍需报告。不能无限执行旧计划，也不能把转角突然归零当作通用安全动作；恢复时还要检查新结果身份、期限与当前状态。

### 9.17 S 曲线制动与停车距离（S-curve Braking / Stopping Distance）

- **英文与含义：** S 曲线制动通过限制 jerk，逐渐建立和释放减速度；停车距离是从规定起点到停止的累计行驶距离，须说明是否包含处理、传输和执行延迟。
- **本项目用途：** 按初速度、可用减速度、jerk 和延迟生成纵向候选，积分得到速度与位置，再与冲突区比较。物理不可避时仍记录碰撞及减损，而非返回虚构停车成功。
- **易混点：** 理想恒减速度下的制动距离不能直接充当有延迟和有限 jerk 的实测停车距离。模型积分还要处理停止时刻、避免负速度和停车保持，并以执行器标定核对有效范围。

### 9.18 热启动与独立解检查（Warm Start / Solution Validation）

- **英文与含义：** Warm Start 用先前有效解作为新求解的初始猜测，可能减少迭代；Solution Validation 则在求解后独立检查数值、约束残差、身份和有效时间，而不是只相信求解状态字符串。
- **本项目用途：** 在当前状态和计划仍相容时复用适当初值，求解后再检查道路包含、车体运动、执行期限和风险。保存原始解、残差及拒绝原因以便复核。
- **易混点：** 热启动不是直接执行上一次计划。场景切换、状态突变或旧解过期时必须重新验证；得到有限数值也不代表约束成立，超时结果不能因路径看起来合理而被采用。

## 10 仿真与调度

依据：[工程设计](工程架构与文件结构设计.md)、[技术路线第5章](详细技术路线.md)。CARLA 原理见[官方同步与步长说明](https://carla.readthedocs.io/en/latest/adv_synchrony_timestep/)。

### 10.1 CARLA 仿真平台

- **英文与含义：** CARLA 是提供道路、交通参与者、传感器和车辆动力学的自动驾驶研究仿真平台，名称作为专名保留。
- **本项目用途：** 构造盲区来车、行人和骑行者场景，生成 RGB 输入并实际执行算法给出的车辆控制。
- **易混点：** 播放既有视频不等于运行闭环；仿真器暴露的全局状态不能直接传给正式在线核心。版本兼容性需实测冻结。

### 10.2 仿真步进与唯一所有者（Tick / Single Owner）

- **英文与含义：** tick 是让仿真世界前进一个步长；single owner 表示只由一个指定调度器发起推进。
- **本项目用途：** 先提交控制，再推进世界并收集对应帧观测，确保车端、路侧和评测共享明确时序。
- **易混点：** API 查询或前端播放不能额外调用 tick；多进程各自推进会改变时间和场景，破坏因果性及配对条件。

### 10.3 同步模式与固定步长（Synchronous Mode / Fixed Time Step）

- **英文与含义：** 同步模式控制何时推进；固定步长规定每次推进多少仿真时间。两者是不同设置。
- **本项目用途：** 起步设计基础步长0.05秒，感知／规划0.10秒；按 frame_id 与采集时间配帧，避免回调顺序错配。
- **易混点：** 20Hz 仿真设计不等于机器能实时完成20Hz计算；相机回调晚到时也不能将图像视作早已可用。

### 10.4 物理子步（Physics Substepping）

- **英文与含义：** 在一个较大仿真步内，以更小时间间隔更新物理计算，提高积分和碰撞计算的稳定性。
- **本项目用途：** 配置需满足仿真步长不超过最大子步长乘最大子步数，并冻结相关设置。
- **易混点：** 子步设置合理不等于实验完全确定；仍需核对车辆行为、传感器帧和重复运行偏差。

### 10.5 独立工作进程与非阻塞执行（Worker / Non-blocking Execution）

- **英文与含义：** worker 执行耗时推理或优化；非阻塞表示执行循环不等待它无限完成，而是读取当前已经可用的结果。
- **本项目用途：** MPC 求解与20Hz执行分开，结果超时或过期时进入明确回退，记录请求与实际完成时间。
- **易混点：** 增加线程不自动保证实时；计算完成的旧结果也可能因状态已变化而失效，必须检查身份和期限。

### 10.6 只保留最新待处理任务（Latest-only Queue）

- **英文与含义：** 对高频计算请求采用有界队列，淘汰尚未处理的旧任务，优先计算最新场景。
- **本项目用途：** 防止感知或规划积压，使计算持续追赶过时状态；淘汰原因应进入运行记录。
- **易混点：** 计算任务队列、轨迹历史和危险目标记忆是三种用途；不能因只算最新任务而把历史或已知危险目标清空。

### 10.7 代次、请求身份与过期结果（Generation / Request ID）

- **英文与含义：** generation 区分重置前后代次，request_id 区分一次计算请求，结合 run、episode、帧号共同确定结果身份。
- **本项目用途：** 场景重置后，上一片段返回的控制结果即使格式合法也应被拒绝。
- **易混点：** 只比较时间或请求序号可能不足以排除跨场景旧结果；wall-clock 时间相近不能证明属于当前仿真。

## 11 评测、实验与统计

本节对应 [研究方案](毕业设计研究方案.md)、[技术路线](详细技术路线.md)、[数据方案](数据来源与验证方案.md)及[节点计划](项目节点实施与验收计划.md)中的评价口径。各指标须同时报告数据域、对象、时域、阈值、有效分母与失败情况；定义指标不表示已经获得实验结果。

### 11.1 平均与终点位移误差（ADE / FDE）

- **英文与含义：** ADE 为 Average Displacement Error，未来各有效时刻位置距离误差的平均；FDE 为 Final Displacement Error，声明终点的位置误差。
- **本项目用途：** 在同一预测时域、单位及有效掩码下评价 CV、GRU、HiVT 和 RC-STGT。通常以米报告，并保存逐目标结果。
- **易混点：** 时域不同不能直接混比；缺失预测不能被悄悄删除。轨迹误差较小不自动意味着危险召回更高、概率更准或闭环碰撞更少。

### 11.2 多模式最优误差（minADE / minFDE）

- **英文与含义：** 分别在 K 条候选轨迹中选择 ADE 或 FDE 最小者，评价模型候选集合是否包含接近真实未来的路径。
- **本项目用途：** 多模式模型按相同 K、时域和掩码评分，CV 单模式明确 K=1。minADE 与 minFDE 的最优模式可能不同，须固定实现口径。
- **易混点：** 最优模式使用真实未来挑选，属于离线评分；在线决策不能读取该模式编号。候选越多可能更容易覆盖真实路径，因此模式数和计算预算必须公开。

### 11.3 预测未命中率（Miss Rate / MR）

- **英文与含义：** 在声明的距离阈值和轨迹判定规则下，预测没有命中真实未来的目标比例；常见协议考察最优终点误差是否超阈值。
- **本项目用途：** 与 ADE/FDE 一起检查模型是否遗漏重要走法，并明确阈值、预测时域、模式数以及所有有效对象的分母。
- **易混点：** 不同数据协议的未命中定义可能不同，不能凭缩写默认同一阈值。预测未命中与检测漏检、风险漏报是三个不同层面的失败，须分别统计。

### 11.4 检测重叠与平均精度（IoU / AP / mAP）

- **英文与含义：** IoU 为 Intersection over Union，检测框交并比；AP 汇总某类别精确率与召回率关系，mAP 再按协议跨类别平均。
- **本项目用途：** 三族 YOLO 在相同可见标注上报告 mAP50、mAP50-95，并按小目标、类别和遮挡分组；具体阈值集合与平均方式随评测协议固定。
- **易混点：** mAP 不是普通分类准确率，也不能代替跟踪连续性、定位误差和闭环效果。mAP50 与多 IoU 阈值平均的 mAP50-95 不可直接当成同一指标。

### 11.5 召回率与精确率（Recall / Precision）

- **英文与含义：** Recall=TP/(TP+FN)，衡量真实正例找回多少；Precision=TP/(TP+FP)，衡量系统报出的正例有多少正确。
- **本项目用途：** 检测层按目标匹配计算，风险层按预先定义的危险事件计算。例如真实危险 10 次检出 8 次，危险召回为 80%，并保留未检出事件。
- **易混点：** TP、FP、FN 的定义和匹配单位必须先冻结。检测置信度阈值改变会同时影响召回和精确率，不能只挑一个更好看的数值评价模型。

### 11.6 误警、漏报与误干预（False alarm / Miss / False intervention）

- **英文与含义：** 误警是对非危险事件报警；漏报是未能报告定义中的危险；误干预是没有必要的制动或转向，三者关注点不同。
- **本项目用途：** 分别报告危险事件漏报、无人负例的告警频率及控制误干预，并说明按场景、事件还是每小时统计。
- **易混点：** “误警率”可能指不同分母，不能省略定义。成功制动后没有碰撞，不证明此前是误警；应参考无干预分支或预先定义的代理事件。

### 11.7 开放环与闭环评价（Open-loop / Closed-loop evaluation）

- **英文与含义：** 开放环在固定输入记录上评价模型，动作不改变后续数据；闭环将动作施加于环境，再根据新状态继续观测与决策。
- **本项目用途：** TFD 评价已有轨迹上的预测，SPD 评价真实图像感知及预测链；CARLA 闭环才实际执行制动、转向并记录结果。
- **易混点：** 固定日志上的低风险或低误差不能证明新控制策略减少真实道路碰撞。播放已保存视频也不是重新运行闭环，两类结果必须分别表述。

### 11.8 真值与上界实验（Ground truth / Oracle upper bound）

- **英文与含义：** Ground truth 是供训练标签或评测使用的参考真实状态；oracle upper bound 是获得额外理想信息的对照实验。
- **本项目用途：** 仿真全局目标状态可用于离线碰撞评分；若用完整真值驱动算法，则标记 oracle_upper_bound，单列于合法观测输入的主结果之外。
- **易混点：** 正式在线核心不能读取隐藏目标、未来帧或真实未来。受可见性与时延约束的 trajectory_input 和完整全局真值上界也不是同一种输入条件。

### 11.9 配对实验（Paired experiment）

- **英文与含义：** 在相同基础条件下分别运行多个方法，再按同一场景身份比较差值，以减少场景难度差异的干扰。
- **本项目用途：** 同一遮挡路口配置分别运行无干预、仅车端 AEB、车路协同 AEB，共享干预前条件、外车脚本和预登记通信扰动。
- **易混点：** 按 scenario_id 和种子身份连接记录，不能按表格行号相减。仅设置相同初始位置不保证完整仿真状态相同，配对前状态偏差和缺配对均须记录。

### 11.10 消融实验（Ablation study）

- **英文与含义：** 有控制地移除或替换某个模块，观察性能变化，用于检验该模块对整体结果的贡献。
- **本项目用途：** 例如关闭来源可靠性门控，其余数据划分、训练预算、感知和控制配置一致，对比延迟条件下的预测和危险召回。
- **易混点：** 仅修改配置名称不算消融，必须改变实际计算路径。同时更换数据、模型和阈值会混入其他原因；负结果和资源差异也需要保留。

### 11.11 泛化与冻结协议（Generalization / Frozen protocol）

- **英文与含义：** 泛化关注未用于训练和选型的条件；冻结协议是在正式测试前确定数据、模型、阈值、指标和比较规则。
- **本项目用途：** 留出未见布局或遮挡条件，模型验证集负责选型，风险校准集负责校准和阈值，冻结后再评价项目独立测试。
- **易混点：** 名称不同的数据集仍可能同源，TFD 与 SPD 须核查重叠。看过测试趋势后调参、挑场景或选择停止时间，会破坏独立评价的含义。

### 11.12 随机种子与独立样本（Random seed / Independent sample）

- **英文与含义：** Seed 控制伪随机过程的起点；独立样本是统计分析中的独立观察单位，二者不能直接等同。
- **本项目用途：** 分别登记训练初始化种子、场景种子和通信扰动种子；学习模型保留多个训练 seed，场景重复用于观察同条件波动。
- **易混点：** 同一路口同一场景多跑几次，不自动变成多个独立场景；同 episode 数千帧也不是数千个独立事件。只报告最好 seed 会夸大方法表现。

### 11.13 置信区间与聚类重采样（Confidence interval / Cluster bootstrap）

- **英文与含义：** 置信区间描述估计程序在重复抽样下的覆盖性质；bootstrap 通过重采样近似估计不确定性，聚类版本以独立组为单位。
- **本项目用途：** 按独立场景或原始序列重采样配对差值，固定索引和随机种子，报告 95% 区间、有效配对数及原始结果。
- **易混点：** 不能把同场景帧当独立样本。该次区间不是“参数有 95% 概率落在其中”；零碰撞样本产生的退化区间也不能证明真实风险为零。

### 11.14 统计功效与样本量（Statistical power / Sample size）

- **英文与含义：** 统计功效是在预定检验与条件下识别真实差异的能力；样本量需结合事件率、差异大小及目标不确定性确定。
- **本项目用途：** 正式实验前用开发或验证数据估计所需独立场景数，预先声明最小有意义差异、区间宽度及增加样本的规则。
- **易混点：** 达到计划中的最低场景数不保证统计功效足够。事件太少或区间过宽应写证据不足，不能看到测试趋势后选择性追加或停止来追求显著结果。

### 11.15 分母、覆盖与失败记录（Denominator / Coverage / Failure accounting）

- **英文与含义：** 分母说明指标针对多少对象或事件；覆盖说明哪些对象具备可评价输入；失败记录保留未完成、漏检和损坏运行等情况。
- **本项目用途：** SPD 同时报告全部目标、共同可预测目标、未发现目标与关联失败；闭环报告完整预登记场景及失败，不只汇总成功视频。
- **易混点：** 只保留成功预测会使误差虚假变小。失败不能一概当作数值零，也不能静默剔除；不同指标可以有合法不同分母，但须说明排除原因与数量。

### 11.16 不均衡识别与概率质量（PR-AUC / Brier score / Reliability diagram）

- **英文与含义：** PR-AUC 汇总精确率与召回率曲线；Brier score 衡量事件概率与二元结果的平方误差；可靠性图比较预测概率和实际发生频率。
- **本项目用途：** 在危险事件稀少时评价预警识别和风险校准，绑定同一事件定义、参考策略、时域及类别；概率校准只用独立校准资料。
- **易混点：** 识别排序好不等于概率准确，普通准确率高也可能只是多数样本安全。多模式分类权重、检测分数和原始几何评分不能未经校准直接当作碰撞概率。

<a id="section-12"></a>

## 12 工程接口与复现

依据：[N02 数据契约字典](N02数据契约字典.md)、[工程设计](工程架构与文件结构设计.md)、[开发与 Git 协作规范](开发与Git协作规范.md)。

### 12.1 数据契约与版本（Schema / Schema Version）

- **英文与含义：** Schema 规定字段名、类型、形状、单位、允许值及对象之间的约束，版本用于识别契约差异。
- **本项目用途：** N02 对未知字段、重复 JSON 键、非法数值和不支持版本拒绝接收，使车端与路侧对同一消息有一致理解。
- **易混点：** JSON 能解析不等于消息合法；字段齐全也不等于时间已可用、来源可信或控制安全。

### 12.2 接口协议与依赖边界（Protocol / Interface）

- **英文与含义：** 接口定义模块接受什么、返回什么及调用约束；Python Protocol 可表达满足哪些方法和类型即可被使用。
- **本项目用途：** 让 CARLA、预测器和展示层通过明确对象接入，核心包不依赖全局仿真句柄。
- **易混点：** 声明接口和创建空目录不等于实现能力；轻量包导入也不能自动加载权重、初始化 CUDA 或连接服务器。

### 12.3 本车状态与观测包（EgoState / ObservationPacket）

- **英文与含义：** EgoState 表达本车位置、速度、航向等状态；ObservationPacket 封装同坐标与时钟约定下的一批目标观测。
- **本项目用途：** 将不同数据源适配成核心能消费的统一对象，随对象保留采集、处理、外推时间和有效掩码。
- **易混点：** 统一字段格式不保证误差相同；观测包不是仿真全局真值列表，未知字段不能用默认零值冒充测量。

### 12.4 内部预测张量（PredictionBundle）

- **英文与含义：** 内部 NumPy 预测容器，轨迹形状为 `[B,N,K,T,2]`，分别表示批量、目标、模式、未来时刻及二维坐标。
- **本项目用途：** 同时携带 `[B,N,K]` 权重、逐点有效掩码、未来时间和模型标识，为风险模块提供统一输入。
- **易混点：** 它当前不提供 JSON 序列化；不同目标同一个 k 不是天然配套的联合未来场景，T 也不在所有任务中固定40。

### 12.5 传输消息与接收封装（PredictionMessage / ReceivedMessage）

- **英文与含义：** PredictionMessage 是发送侧的预测消息；ReceivedMessage 在接收侧把 payload 与 arrival_time、usable_time 封装在一起。
- **本项目用途：** 发送端描述原始预测时间和内容，接收端记录实际何时到达、何时完成处理并可用于决策。
- **易混点：** 发送侧不能替接收侧填写到达和可用时间；内部张量、传输消息和接收元数据不能混作一个对象。

### 12.6 决策与控制结果（DecisionBundle / ControlResult）

- **英文与含义：** DecisionBundle 表达动作模式、风险口径、参考与求解请求；ControlResult 表达求解状态、复核标记、控制请求及失败／回退原因，实际执行只采用当前有效且复核通过的结果。
- **本项目用途：** 将“打算怎样避让”与“当前可提交哪些油门、制动、转向”分开，使原因和期限可追溯。
- **易混点：** 控制数值位于合法范围不代表物理上一定可行；请求生成、求解完成和执行复核是不同环节。

### 12.7 最终配置与配置覆盖（Resolved Configuration / Override）

- **英文与含义：** resolved config 是默认值、基础配置、任务、脚本覆盖和显式命令行覆盖合并后的实际配置。
- **本项目用途：** 把本次真正使用的数据路径、时域、种子和资源选项保存下来，使 IDE 与命令行运行口径一致。
- **易混点：** 未传 CLI 的默认值不能意外盖掉任务文件；0 和 False 是有效配置值，不能当成“没有提供”。

### 12.8 运行清单与产物（Run Manifest / Artifact）

- **英文与含义：** manifest 是一次执行的身份和输入输出索引；artifact 是实际产生的日志、质量报告、模型、预测或视频等材料。
- **本项目用途：** 关联 run_id、源码版本、配置、数据、权重哈希、环境、种子、输入模式和完成状态。
- **易混点：** 清单中写有路径不保证文件仍存在；必须验证产物可取得且完整，中断输出不能标为完整成功结果。

### 12.9 内容哈希与代码提交（SHA-256 / Git Commit）

- **英文与含义：** SHA-256 给内容生成指纹；Git commit 固定一个仓库版本及其父子关系。
- **本项目用途：** 将表格、图像和指标追溯到不可变源码、配置、数据和权重；节点结果引用实际被测提交。
- **易混点：** 哈希一致说明相应内容一致，不自动证明来源、数据许可或算法正确；HEAD 与 main 会移动，不能单独用作被测版本。

### 12.10 依赖声明、锁文件与环境（pyproject.toml / uv.lock / Virtual Environment）

- **英文与含义：** 依赖声明说明项目要求，锁文件保存依赖解析结果，虚拟环境保存本机实际安装的解释器相关软件。
- **本项目用途：** 使用 uv 准备可重建的轻量环境，并在对应节点验证训练、控制或桥接依赖。
- **易混点：** 有锁文件不等于所有系统和 GPU 已兼容；虚拟环境不适合跨操作系统直接搬运，构建工具也未必全由当前锁文件固定。

### 12.11 GPU、CUDA 与显存（Graphics Processing Unit / CUDA / VRAM）

- **英文与含义：** GPU 是并行计算硬件，CUDA 是 NVIDIA GPU 计算平台，VRAM 是设备上的显存；三者不是同一项资源。
- **本项目用途：** N06 在真实目标设备上验证张量、前反向、参数更新、同步耗时与峰值显存，并冻结训练预算。
- **易混点：** 能显示 GPU 名称不等于模型可训练；CPU 诊断、Mac 检查和目标显卡实测不能互相替代。本文不推荐或固定驱动版本。

### 12.12 IDE 直接运行与命令行（IDE / CLI）

- **英文与含义：** IDE 是集成开发环境；CLI 是命令行接口。直接运行意味着入口有明确默认任务，不要求填写必填命令行参数。
- **本项目用途：** 选择准备好的解释器后点运行；路径依据脚本与项目位置解析，批量任务再用可选 CLI 显式覆盖。
- **易混点：** 无参数入口不表示自动准备所有数据或依赖；缺项必须失败并说明原因，不能自动伪造数据或成功结果。

### 12.13 API、前端与只读观察层（Application Programming Interface / Frontend）

- **英文与含义：** API 提供结构化数据访问；前端将视频、轨迹、风险和指标组织成可操作页面。
- **本项目用途：** FastAPI 提供 Python 查询接口，Vue 组织页面组件，TypeScript 提供静态类型约束，Vite 负责开发服务与构建，ECharts 绘制图表；BEV（Bird's-Eye View）指鸟瞰视图。
- **易混点：** 页面不直接运行训练、产生避撞控制或推进 CARLA；关闭观察层后算法仍应独立工作，概念图不能冒充实际界面。

### 12.14 机制检查、回归与验收（Mechanism Test / Regression / Acceptance）

- **英文与含义：** 机制检查用可手算夹具验证定义，回归检查修改是否破坏既有行为，验收确认指定范围达到约定要求。
- **本项目用途：** 区分文档静态检查、CPU 机制、GPU 训练、CARLA 闭环和用户验收，并分别保存真实证据。
- **易混点：** 自测通过不等于用户验收；用户验收不自动授权下一节点。未运行、失败或跳过不得记为通过。

### 12.15 数组、数据表与科学计算（NumPy / pandas / SciPy）

- **英文与含义：** NumPy 提供多维数值数组；pandas 组织带字段的数据表；SciPy 提供建立在数值数组上的科学计算算法。
- **本项目用途：** 分别处理轨迹张量、审计或指标表，以及线性分配等算法；具体依赖在对应节点准备和验证。
- **易混点：** 工具库名不说明采用了哪种算法；表格合并还要核对键和数据粒度，不能因代码跑通就认为关联正确。

### 12.16 配置与记录格式（YAML / JSON / JSONL / CSV）

- **英文与含义：** YAML 用缩进等结构表达配置；JSON（JavaScript Object Notation）表达结构化对象；JSONL 每行一个 JSON 值；CSV（Comma-Separated Values）保存分隔字段的表格。
- **本项目用途：** 用 YAML 指定任务，JSON 保存清单，JSONL 记录事件或转换轨迹，CSV 汇总可检查指标；当前审计还支持 gzip 压缩的 JSONL。
- **易混点：** 格式不自动提供单位、类型和业务约束；JSONL 中断文件可能只有部分完整行，不能据文件存在宣称整次审计完成。

### 12.17 列式存储、压缩与本地索引（Parquet / gzip / SQLite）

- **英文与含义：** Parquet 是列式数据文件格式；gzip 是无损压缩格式；SQLite 是可用本地数据库文件保存结构化记录的嵌入式数据库。
- **本项目用途：** 设计中用列式文件保存处理表，用压缩降低大审计输出占用，用数据库索引定位运行和报告；实际已建能力以仓库和节点为准。
- **易混点：** 压缩不能保证任意规模都装得下，也不改变样本语义；拥有数据库索引不能替代原始产物，更不能把计划使用的格式写成已经全部实现。

## 13 易混概念与贯穿算例

### 13.1 易混概念对照

| 容易混淆的概念 | 应如何区分 |
| --- | --- |
| 协同感知／协同避让 | 前者共享环境信息；后者交换动作意图并协调多辆车运动。 |
| 检测／跟踪／跨源关联 | 检测找单帧目标；跟踪连接同视角多帧；跨源关联判断车端与路侧记录是否属于同一对象。 |
| 图像框／地面 OBB | 前者在像素坐标描述可见外观；后者在米制地面坐标描述实际车体占用。 |
| 原始观测／滤波外推 | 观测提供新证据；外推只是根据旧证据和运动模型估计当前状态。 |
| 多模态预测／多传感器输入 | 本文多模态预测指多种未来走法；多传感器指不同观测来源或数据类型。 |
| 模式权重／碰撞概率 | 前者描述未来候选的相对权重；后者必须绑定动作、事件、时域并经过适用校准。 |
| 消息到达／业务可用 | 到达后仍可能等待重组、解码与校验；决策只能消费已经可用的消息。 |
| 消息有效期／预测覆盖 | 尚未过期不保证轨迹覆盖整个计划区间，逐目标缺失也不能由全局 future_end 掩盖。 |
| Transformer／MPC | 前者预测周围对象；后者根据本车运动模型优化控制，上游还需候选动作与风险筛选。 |
| 原始风险／未知区约束 | 有观测目标可计算声明条件下的评分；未知区只能表达谨慎约束，不能编造隐藏目标概率。 |
| 真实数据／实车控制验证 | 真实日志能评价感知和预测；改变车辆行为后的结果须由可交互实验检验。 |
| 训练种子／独立场景 | 多个训练种子反映训练波动；相同场景重复运行不等于新增独立场景。 |

### 13.2 从观测到决策的时间例子

设目标在0秒被真实观测，位置为0米、速度为10米／秒。滤波器把状态外推到0.2秒，得到 `state_time=0.2`、位置2米，但 `last_seen_time` 仍为0秒。若预测锚点为0.3秒，应从状态时刻再外推0.1秒，得到3米，不能从旧采集时刻再加0.3秒而得到5米。

另设一条预测的 `anchor_time=12.0`、`future_end=16.0`，12.2秒到达，12.25秒完成校验后可用。12.22秒不能消费该消息；到12.25秒使用时，原锚点仍是12.0秒。计划从12.25秒执行3秒，需要覆盖到15.25秒；若拖到13.1秒才执行，同样3秒计划需要覆盖到16.1秒，原预测已不足，即使消息还没过有效期也不能照常放行。

### 13.3 模式评分、动作与标签例子

设同一目标有直行和左转两个未来模式，权重分别为0.7与0.3。在声明的未来时域内，若本车“保持速度”只与第一模式发生几何冲突，原始模式加权事件评分是0.7。更换本车动作、改变时域或增大保护裕量后，事件定义已经变化，需要重新评估，不能机械沿用同一评分或阈值。

若本车最终刹车并没有碰撞，这只描述制动分支的结果。要判断先前告警是否合理，还要看同初始条件的无干预分支或预先定义的代理事件；不能把所有成功干预后的无碰撞样本都记为误报。

### 13.4 从带宽到控制期限的例子

一条消息为38,400字节，信道容量为1,000,000 bit/s，仅发送服务时间就为 `8×38400/1000000=0.3072` 秒，尚未计传播、处理等延迟。若每0.1秒产生同样大的消息，长期输入超过容量，必须出现排队或按冻结规则淘汰，不能仍报告全部零排队送达。

这个例子解释为什么要分别记录消息年龄、剩余预测覆盖和端到端耗时；它不代表真实 C-V2X 设备测速。求解器算完也不意味着结果可立即使用，还要经过执行侧身份、期限与安全复核。
